# J1 contract: Judge one case with vet run

Status: reference. This document records the contract that slice J1 implements and that every
J1 leaf builds against. It changes no code itself; it is enforced by the tests named in
"Enforced by" below. Facts are copied verbatim from the root epic ledger
(`bd show classified-evals-d4m`) and the bead payload for `classified-evals-mol-8wz`. UNVERIFIED
markers are kept as written where they occur — this document invents none.

## Why

J1 is the first runnable journey: a developer hand-writes one criterion and one case, runs
`vet run`, and gets a typed verdict with a recorded model identity, a cache hit on the second
run, and a CI-usable exit code. Everything later (generation, calibration, export, OTel) builds
on the IR and the `JudgeV1` port fixed here. Implements DECISION: Judge engine is TypeSafe Jev,
DECISION (access layer), DECISION (pinning honesty, supersedes earlier pinning amendments),
DECISION: Architecture as presented in the brainstorm.

## Context

Consumer: the developer at the terminal and their CI job.

Command: `vet run [--json] [--gate] [--allow-unpinned] [--config vetkit.config.ts]`.

Library: `runEvals({ config, signal }) → { results: Verdict[], summary: { total, passed, failed,
unscored }, model }`.

Consumer-first contract (DECISION: Architecture as presented in the brainstorm): the developer
runs `vet run` once; the library function behind it is `runEvals(config)` in `@vetkit/core`. No
table-first API.

## Ports (`packages/spec/src/ports/judge.ts`)

```ts
type Question =
  | { type: 'boolean'; instructions: string }
  | { type: 'choice'; instructions: string; criteria: Record<string, string> }
  | { type: 'score'; instructions: string; criteria: string[] }; // 2..10 levels

interface JudgeV1 {
  specVersion: 'v1';
  id: string;
  capabilities: {
    questionTypes: Array<Question['type']>;
    maxStateTokens: number;
    pinned: boolean;
    transport: string;
    model: string; // declared/requested model id (cache key, unscored model.requested)
  };
  doJudge(req: {
    state: string;
    questions: Record<string, Question>;
    signal?: AbortSignal;
  }): Promise<JudgeResponse>;
}

interface JudgeResponse {
  answers: Record<string, Answer>;
  usage: { inputTokens: number; outputTokens: number };
  model: {
    requested: string;
    resolved: string;
    transport: string;
    pinned: boolean;
    provider?: string;
    credentialType?: string;
    releaseDate?: string;
  };
  raw?: unknown;
}

type Answer =
  | { type: 'boolean'; probability: number }
  | { type: 'choice'; choice: string; confidence: number; probabilities: Record<string, number> }
  | {
      type: 'score';
      score: number;
      confidence: number;
      legend: Record<string, string>;
      probabilities: Record<string, number>;
    };
```

Question type names are `boolean|choice|score` in the IR; adapters map boolean↔TypeSafe `noul`
at the wire edge (`docs/research/2026-09-25-provider-agnostic-access-layer-brief.md` §5
conflict 6). Every boolean criterion is compiled to a 3-way choice `{yes, no, escape}` at the
wire edge (Stage B escape DECISION); the spike (`docs/contracts/js.md`) confirmed this mapping
and that Jev never abstains unless an escape option exists.

`JudgeResponse.model` fields are DECISION (pinning honesty, supersedes earlier pinning
amendments): every judgment records `{requestedModel, resolvedModel, transport, pinned}`. Vercel
gateway and Cloudflare are `pinned:false` (alias only); TypeSafe direct (`jev-1.13.0`) and
OpenRouter (`typesafe/jev-1.13`, served build echoed as `typesafe/jev-1.13-20260917`) are
`pinned:true`. `vet run --ci` refuses to gate on a lock made through an unpinned transport
unless `--allow-unpinned` is passed. Vercel stays the zero-setup default for authoring/
exploration (DECISION, access layer brief).

## IR (schemas → generated types)

```ts
interface Criterion {
  id: string;
  type: Question['type'];
  instructions: string;
  criteria?: Record<string, string> | string[];
  escape: string;
  passWhen?: string[]; // required for choice (at least one label); absent otherwise
  escapeThreshold?: number;
  polarity: 'pass_when_true' | 'pass_when_false';
  channel: 'outcome' | 'safety' | 'quality';
  provenance: { traceIds: string[]; generator?: string };
  wordingHash: string;
  checkable?: 'factual' | 'math' | 'code';
  grader?: { kind: 'judge' | 'reference' } | { kind: 'code'; check: 'exact' | 'normalized' | 'numeric' };
}

interface Case {
  id: string;
  input: { state: string; answer?: string };
  traceId?: string;
  provenance: unknown;
  tags: string[];
  expected?: { value: unknown; source: 'user' | 'code_verified' };
  language?: string;
  cluster?: string;
}

interface Verdict {
  caseId: string;
  criterionId: string;
  status: 'ok' | 'unscored' | 'error' | 'incomplete_trace' | 'truncated' | 'content_not_captured'
    | 'not_applicable' | 'infra_failure' | 'simulator_error';
  answer?: Answer;
  pass?: boolean;
  threshold?: number;
  model: JudgeResponse['model'];
  cacheHit: boolean;
  cause?: unknown;
  explanation?: string;
  gated?: boolean;
  gateReason?: 'score_not_gateable' | 'language_not_calibrated';
  borderline?: boolean;
  calibrated?: boolean;
}
```

`Verdict.status` is a discriminated union, never a throw (DECISION: Code conventions).
`Verdict.threshold` is absent when `status != 'ok'`. Thresholds are on the pass-value scale
calibrate fits on: P(yes) for boolean, the expected level E for score, inverted to 1 − p or
max − E for `pass_when_false`. `Criterion.passWhen` (choice only and
required for choice: at least one label, values ⊆ `criteria` keys; no default, so a choice
criterion without it is `CRITERIA_INVALID`) and `Criterion.escapeThreshold` (0..1, default 0.5) are DECISION (turn 9,
contract amendment): present in `classified-evals-mol-0nw.1`'s payload Approach and consumed by
`mol-0nw.6`/`mol-0nw.7`/`mol-0nw.9`, restored here after being dropped from this contract; fixed
under bug `classified-evals-mol-0nw.12`. `Criterion.checkable`/`grader`, `Case.
expected`/`language`/`cluster`/`input.answer`, and `Verdict.gated`/`gateReason` are the optional
fields added by DECISION (eval-quality brief applied, 2026-09-26), items 9, 11 and 12 (cluster: item 12, near-duplicate report):
`Case.expected` plus a reference/code grader is required for checkable factual/math/code
criteria to reach calibrated status; only boolean/choice criteria gate today — score verdicts
are `gated:false`, `gateReason:'score_not_gateable'` until the JS spike measures score
calibration (item 14).

JSON Schema 2020-12 IR, validated by `ajv@8` through `safeParseJson` (DECISION: JSON Schema
validation, Stage B). Standard Schema types are copied into `@vetkit/spec` rather than taken as a
dependency (`docs/research/2026-09-25-provider-agnostic-access-layer-brief.md` §2.2).

## Cache key

`sha256(state, wordingHash, model.resolved)` — content-addressed, so a wording change or a model
resolution change (even under the same alias) invalidates the cache; the cache itself lives
under `.vet/cache` and is out of scope for this contract (owned by `classified-evals-mol-0nw.6`).

## One-request-per-case rule

For one case with N criteria, exactly one `JudgeV1.doJudge` call is made, carrying N questions
keyed by criterion id. This bounds the judge call budget to one command → one Jev request per
case, matching the atomic-question design in
`docs/research/2026-09-25-jev-eval-generation-brief.md` §2.

## Exit codes

- `0` — all cases pass.
- `1` — at least one case fails its threshold.
- `2` — gating refused (uncalibrated, unpinned without `--allow-unpinned`, or config error).

Never any other code for these three outcomes (root acceptance J1/J3 lines). DECISION (turn 8,
corrects turn-7 43x error table): class rules match with or without the `E_` prefix
(`CONFIG_*`/`E_CONFIG*` → 2, `NOT_INTERACTIVE` → 2, `GATE_*` → 2, `UNSCORED_ONLY` → 3,
`SINK_*`/`SOURCE_*` → 0 warn / 1 strict), because this contract fixes literal unprefixed codes
(`CONFIG_INVALID`, `GATE_REFUSED`, …) alongside the existing `E_`-prefixed spec codes. Fixed
under bug `classified-evals-mol-p4a.5`.

## Edge cases

- `score.criteria` with fewer than 2 or more than 10 levels: schema rejects (TypeSafe 2–10, the
  strictest bound across transports).
- `choice` without an escape key present in `criteria`: schema accepts; the linter (J2) rejects —
  this contract only requires the `escape` field to name a key, not that the key already exist in
  `criteria`.
- `Verdict.threshold` absent when `status != 'ok'`.
- `model.pinned` is `false` on the Vercel and Cloudflare transports — `Verdict` must still be
  valid.
