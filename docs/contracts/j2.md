## Why

J2 is the product's differentiator: it turns traces a team already has into atomic, typed,
provenance-carrying criteria and cases, with a linter that rejects questions Jev is known to
answer badly. Implements DECISION: Two-model design, DECISION (access layer, from
`docs/research/2026-09-25-provider-agnostic-access-layer-brief.md`), DECISION (structured
output), DECISION (resolves OPEN-2, user 2026-09-25), DECISION (resolves OPEN-6, user
2026-09-25).

## Context

Consumer: developer at the terminal.

Commands: `vet init --source <path>|jsonl:<path> [--out evals/] [--max-criteria N] [--json]` and
`vet lint [evals/criteria.yaml] [--json]`.

Library: `generateEvals({ config, source, generator, judge, out, signal }) → { criteria:
Criterion[], cases: Case[], report: { failureModes: FailureMode[], rejected: LintIssue[] } }`;
`lintCriteria(criteria) → LintIssue[]` where `LintIssue = { ruleId, criterionId, path, message,
severity:'error'|'warn' }`.

## Ports (`packages/spec/src/ports/source.ts`, `generator.ts`)

```ts
interface SourceV1 {
  specVersion: 'v1';
  id: string;
  capabilities: { streaming: boolean; content: 'captured' | 'maybe' | 'never' };
  doRead(opts: { signal?: AbortSignal }): AsyncIterable<NormalizedTrace>;
}

interface GeneratorV1 {
  specVersion: 'v1';
  id: string;
  capabilities: { structured: 'json_schema' | 'json_object' | 'tool' | 'prompt'; streaming: boolean };
  doGenerate(req: {
    system?: string;
    prompt: string;
    schema?: { name: string; jsonSchema: JsonSchema };
    signal?: AbortSignal;
  }): Promise<{
    value?: unknown;
    text?: string;
    usage?: { inputTokens?: number; outputTokens?: number };
    resolvedModelId?: string;
  }>;
}
```

Both ports follow the same `specVersion` + `capabilities` + `defineAdapter`/`requireCapabilities`
discipline as `JudgeV1` (`docs/contracts/j1.md` "Ports"; `packages/spec/src/registry.ts`,
already generic over `AdapterKind`). A stranger implementing a `SourceV1` or a `GeneratorV1`
needs only this file and `trace.schema.json` — never `@vetkit/core` (DECISION: Bun and library
architecture, adapters import only `@vetkit/spec`).

`NormalizedTrace { traceId, spans[], messages: Message[] (role user|assistant|system|tool,
content parts text|tool_call|tool_call_response), dialect, schemaUrl?, completeness:
{contentCaptured, truncated, missingParents}, tokens? }`.

`GeneratorV1.capabilities.structured` names one of four declared strategies
(`json_schema|json_object|tool|prompt`); the strategy is read from this declared capability and
never auto-detected at runtime (DECISION (structured output)). `doGenerate`'s `schema` carries
JSON Schema 2020-12 (the same IR dialect as `Criterion`/`Case`/`Verdict`); each generator adapter
owns its own down-conversion and strict per-dialect normalisation, and every returned `value` is
re-validated client-side against the requested schema before use (DECISION (structured output)).

## Generation contract

`vet init --source <dir>` is ONE command. Its outputs are:

- `evals/criteria.yaml` — at least 5 criteria surviving lint, each atomic (one lint-checked
  question), typed (`Criterion.type` ∈ `boolean|choice|score`), carrying a non-empty `escape`
  (boolean/choice) and a non-empty `provenance.traceIds`.
- `evals/cases/*.jsonl` — at least 20 cases, each carrying a non-empty `provenance.traceId`.

The generator is called through `GeneratorV1` only — no other network client exists in the
generation pipeline (DECISION: Two-model design: `GeneratorV1` proposes, Jev filters, dedupes
and judges; Jev never generates).

Structured output is validated against the requested JSON Schema before use. A capability
mismatch — the adapter declares `json_object` but a `json_schema` output is required — is a
`GENERATOR_CAPABILITY` error, never a silent downgrade (DECISION (structured output); AI SDK's
openai-compatible provider defaults to `json_object`, Anthropic's OpenAI-compat endpoint ignores
`response_format` entirely).

Generated output never carries a reference: no `Case` written by `vet init` has `expected`
(`Case.expected` is reserved for a user-supplied or code-verified reference, DECISION
(eval-quality research applied, 2026-09-26) item 11). Generated factual/math/code criteria carry
`Criterion.checkable` (`'factual'|'math'|'code'`) so they stay uncalibrated with reason
`reference_missing` until a user reference or a code grader exists — `vet init` and `vet lint`
never write `expected` or a `grader` themselves.

## Call budget

One command → bounded model calls: generator calls ≤ `3 + ceil(traces/20)` (one failure-mode
discovery call, one criteria-proposal call, one case-extraction call per 20 traces). Jev
(`JudgeV1`) calls ≤ 1 per 50 candidate criteria for dedupe, sent only for pair-groups that pass a
deterministic similarity pre-filter first (DECISION (eval-quality research applied, 2026-09-26) item
13: the dedupe budget counts only pair-groups that pass the pre-filter; zero Jev calls when none
qualify).

## File layout of outputs

`evals/criteria.yaml`, `evals/cases/<batch>.jsonl` (batch files under `evals/cases/`, not one
combined file — the `*.jsonl` glob in the generation contract above names the directory
contract, exact batching left to the leaf that writes it).

## Lint rule ids

Ten rule ids are enumerated as an `as const` object in `packages/core/src/criteria/lint.ts`:
`ESCAPE_MISSING`, `DOUBLE_NEGATIVE`, `COMPUTATION`, `NON_ATOMIC`, `FORBIDDEN_WORD`,
`CONTRADICTS_INSTRUCTION`, `INVERTED_BOOLEAN`, `NEGATION_PAIR`, `COMPOUND_LEVEL`,
`DEEP_INDIRECTION`. `INVERTED_BOOLEAN`, `NEGATION_PAIR` and `COMPOUND_LEVEL` are `severity:
'error'`; `DEEP_INDIRECTION` is `severity: 'warn'` (DECISION (eval-quality research applied,
2026-09-26) item 18). Lint rules derive from Jev's documented failure modes (RISK: Jev judge
behaviour — literal reading).

## Error codes

`packages/spec/src/errors.ts`'s `CEV_ERROR_CODES` as-const object gains five new codes, alongside
the 22 existing codes (none removed): `SOURCE_UNREADABLE`, `TRACE_INVALID`,
`GENERATOR_UNAVAILABLE`, `GENERATOR_BAD_OUTPUT`, `GENERATOR_CAPABILITY`. Each round-trips through
`VetError.isInstance` and `.code`, following the same pattern as the J1 codes (owned by
the owning bead — see "Ownership gaps").

## Edge cases

- Source with `content: 'never'` → generation refuses with a `SOURCE_UNREADABLE`-like issue "no
  content captured" (typed status, not a crash).
- Fewer than 5 criteria survive lint → the command still writes what survived and exits 1 with a
  report.
- Generator returns text where JSON was required → `GENERATOR_BAD_OUTPUT` with one retry.

From the root epic ledger, the DECISIONs that name this slice or
its leaves directly:

- DECISION (resolves OPEN-2, user 2026-09-25): JSONL trace export is the trace source for the
  spike and the first runnable journey (J1/J2); OTel (OTLP file, then `:4318` receiver) is the
  first real adapter after that (J5/J6). Rationale: JSONL has no schema-drift risk while GenAI
  semconv is still Development status.
- DECISION (resolves OPEN-6, user 2026-09-25): the generator is model-agnostic and
  provider-agnostic — a `GeneratorV1` adapter interface (generate text / structured JSON from a
  prompt) with the concrete provider chosen in `vetkit.config.ts`; NO provider is hard-coded in
  the library. The first shipped generator adapter speaks the OpenAI-compatible
  chat/completions wire shape with a configurable `baseURL`, which covers Vercel AI Gateway,
  OpenRouter, OpenAI, Anthropic-via-gateway, Ollama and vLLM with one implementation; an AI
  SDK-based adapter is a second package for AI SDK users. Default in the scaffolded config (not
  in code) = whatever key `x doctor` finds first. Trace content leaving the environment to the
  generator provider and to the judge provider is acceptable (user, 2026-09-25); the docs must
  state it and ZDR options must be surfaced per adapter.
- DECISION (access layer, from
  `docs/research/2026-09-25-provider-agnostic-access-layer-brief.md`): no third-party
  abstraction is taken as a dependency. `@vetkit/spec` defines two ports — `GeneratorV1`
  `{specVersion, id, capabilities{structured: json_schema|json_object|tool|prompt, streaming},
  doGenerate({system?, prompt, schema?, signal}) → {value?, text?, usage?, resolvedModelId?}}`
  and `JudgeV1` (question types boolean|choice|score, structurally compatible with AI SDK
  `EvaluationModelV4` but our own contract, `JudgeResult` keeps distribution + confidence +
  `{requestedModel, resolvedModel, transport, pinned}`). Adapters, each its own subpath with at
  most one optional peer: generator `openai-compatible` (≈150-line raw fetch, `response_format
  json_schema`, covers OpenAI/OpenRouter/Vercel gateway/Ollama/vLLM/Groq/Mistral), generator
  `ai-sdk` (import-type only from `@ai-sdk/provider`, optional peer `^3||^4`, duck-types
  `specificationVersion`; documented escape hatch = user passes a function wrapping
  `generateText`), generator `langchain` and `anthropic-native` later; judge `jev` on
  `@typesafe-ai/sdk 0.6.0` (0 deps, injectable `baseURL`+`fetch`) with presets
  typesafe/vercel/openrouter and a small built-in fetch path for Cloudflare, all feeding one
  normaliser; judge `ai-sdk` (`Experimental_EvaluationModelV4`) optional and secondary. `ai` is
  NEVER a dependency of any `@vetkit/*` package (it hard-depends on `@ai-sdk/gateway` +
  `@vercel/oidc` and routes bare strings to Vercel). Config per role =
  `string | {id, baseURL?, apiKey?, headers?} | GeneratorV1 | AISDKModel`, strings resolve only
  through the user's explicit registry, never an implicit env-chosen default (promptfoo #10526,
  autoevals #136).
- DECISION (structured output): core validates every generator output with the schema's
  `~standard.validate`; a capability mismatch is an error, never a silent downgrade (AI SDK
  openai-compatible defaults to `json_object`; Anthropic's OpenAI-compat endpoint ignores
  `response_format`). Strategy `json_schema|tool|prompt` is chosen from the adapter's declared
  capability per endpoint, never auto-detected at runtime. IR stays JSON Schema 2020-12; each
  generator adapter owns down-conversion + strict normalisation per dialect and rejects schemas
  whose meaning would change (e.g. recursive schemas to Anthropic).
- DECISION (eval-quality research applied, user 2026-09-26 "apply that") — the items naming this
