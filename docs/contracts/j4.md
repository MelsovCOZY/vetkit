## Why (verbatim from payload)

Root journey J4: the library never owns the runner; it emits native scorer files teams execute
unchanged. Vitest is first (DECISION (resolves OPEN-7…)); this contract fixes the port, the file
shapes and the parity rule so later exporters copy it.

## Context (verbatim from payload)

Today: no exporters. J1 provides `runCase(config, case, criteria, lock)` in
`packages/core/src/judge/run.ts` and the verdict cache; J3 provides the Lock. Consumer: a vitest
project that imports `@vetkit/core` and the configured judge from its own `vetkit.config.ts`. The
emitted test file imports scorers by relative path and cases from `evals/cases/*.jsonl` at test
time.

(Premise note: `packages/core/src/judge/run.ts` does not exist in this tree yet — see Premise.)

## Emitted file shapes

Verbatim from the acceptance criteria:

- `<outDir>/scorers/<criterionId>.ts` exports `createScorer()` returning `{ name: string, scorer:
  (args:{input:string, output:string, expected?:unknown}) => Promise<{score:number,
  metadata:{criterionId, wordingHash, model:{requested,resolved,transport,pinned}, status,
  probability?, threshold?}}> }` (Evalite-compatible shape).
- `<outDir>/<criteriaFile>.evals.test.ts`: one `describe` per criteria file, one `test` per case,
  asserting `score >= 1` when `pass` and `< 1` otherwise, and `test.skip` with the status name
  when the lock marks the criterion uncalibrated.

`model` in the emitted metadata reuses `JudgeResponse.model`'s field names
(`requested`/`resolved`/`transport`/`pinned`) fixed in `docs/contracts/j1.md` "Ports" — this
contract defines no new model-identity shape. `wordingHash` and `criterionId` reuse
`Criterion.wordingHash`/`Criterion.id` from `docs/contracts/j1.md` "IR".

Verify (AC verbatim): `packages/export-vitest/src/emit-scorer.test.ts` and `emit-test.test.ts`
compile the emitted files with `bun run typecheck` in a temp workspace.

## Parity rule

Verbatim from the acceptance criteria: for every case, vitest pass/fail equals `vet run --json`
pass/fail (same lock, same judge, cache shared via `.vet/cache`).

Verify (AC verbatim): `vet export --to vitest && bun x vitest run --reporter=json evals/vitest >
/tmp/vt.json && vet run --json > /tmp/run.json && node scripts/diff-verdicts.mjs /tmp/run.json
/tmp/vt.json` → 0 differences, exit 0.

The cache key and `.vet/cache` location are fixed in `docs/contracts/j1.md` "Cache key" —
`sha256(state, wordingHash, model.resolved)`; this contract adds no new cache mechanism, it only
requires the emitted scorer to share that cache with `vet run`.

## Approach (verbatim from payload)

Add `packages/spec/src/ports/exporter.ts` (j4-1), `packages/export-vitest` (j4-2, j4-3), `vet
export` in `packages/cli/src/commands/export.ts` (j4-3). Closest example after J1:
`packages/judge-jev` registration via `defineAdapter`.

## Edge cases (verbatim from payload)

Lock absent (scorers still emitted; tests run with threshold 0.5 and `metadata.status:
'uncalibrated'` unless `--require-lock`); a case whose trace is `content_not_captured` (`test.skip`
with the status); judge unscored at test time (test fails with the cause, never a silent pass).

`content_not_captured` is one of `Verdict.status`'s enumerated values fixed in
`docs/contracts/j1.md` "IR" — this contract adds no new status value. The default threshold
`0.5` matches `thresholds.default` in the `vetkit.config.ts` schema described in
`docs/research/2026-09-26-user-and-developer-experience-brief.md` (bead
the owning bead), not a value this contract itself introduces.

## Decisions (verbatim)

- DECISION (resolves OPEN-7, user 2026-09-25, root ledger): first export target = Vitest (scorer
  module + `.test.ts` generation, Evalite-compatible scorer shape); Promptfoo, pytest and Claude
  plugin-eval are later exporters behind the same exporter interface.
- Design note (payload, verbatim): Evalite-compatible `{name, scorer}` shape because every runner
  converges on Case→Scorer→{score, metadata} (`docs/research/2026-09-25-jev-eval-generation-brief.md` §3 'Shared abstraction') and vitest is
  the chosen first target (DECISION (resolves OPEN-7…)). The emitted scorer calls the real judge
  at test time through `@vetkit/core` (real data only; no mock in a shipped path — root testing
  rule). Exporters are adapters that import only spec (DECISION: Architecture…).
- DECISION (2026-09-26, payload verbatim; see `docs/research/2026-09-26-user-and-developer-experience-brief.md`): J4 grows three leaves — JUnit reporter,
  GitHub Action, and the `@vetkit/scorers` judge-only package (Braintrust/Evalite/autoevals
  scorer, promptfoo javascript assertion, vitest matcher). The J4 gate now also requires them.
  (No acceptance-criteria text or verify command for these three leaves is present in this bead's
  payload — see "Enforced by" for how they are handled here.)
