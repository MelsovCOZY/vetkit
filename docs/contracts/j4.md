# J4 contract: Export evals to vitest

Status: reference. This document records the contract for exporting evals to native vitest scorer
files. It changes no code itself; it is enforced by the tests and scripts named in "Enforced by"
below.

## Background

- `packages/spec/src/version.ts` lists `'exporter'` in `ADAPTER_KINDS = ['source', 'generator',
  'judge', 'sink', 'exporter']`, so the exporter kind needs no `version.ts` change.
- `assertSpecVersion` in `packages/spec/src/registry.ts` (called from `defineAdapter`) throws
  `VetError` with code `E_ADAPTER_SPEC_VERSION` on a spec-version mismatch. That registry code
  stands; there is no rename to `ADAPTER_SPEC_MISMATCH`. The registration test asserts
  `VetError.code === 'E_ADAPTER_SPEC_VERSION'` (see "Ports").
- `CEV_ERROR_CODES` in `packages/spec/src/errors.ts` has 22 codes before this contract (the 12
  `E_*` codes plus `CONFIG_INVALID`, `CRITERIA_INVALID`, `CASE_INVALID`, `JUDGE_UNAVAILABLE`,
  `JUDGE_TIMEOUT`, `JUDGE_BAD_RESPONSE`, `GATE_REFUSED`, `CACHE_IO`, `JUDGE_UNAUTHORIZED`,
  `INPUT_TOO_LARGE`). Neither `EXPORT_NO_LOCK` nor `EXPORT_TARGET_UNKNOWN` is among them; this
  contract adds them.
- `resolveExit()` in `packages/cli/src/errors.ts` has an exact-match `CONFIG_EXIT_CODES` set and
  prefix rules for `CONFIG*`, `GATE_*`, `UNSCORED_ONLY`, `SINK_*`/`SOURCE_*`, `NOT_INTERACTIVE`.
  An unmatched code falls through to the `internal` category, exit `70`, so an `EXPORT_*` prefix
  rule mapping to exit `2` is required (see "Enforced by").
- `createProgram()` in `packages/cli/src/program.ts` registers the subcommands; `vet export` lives
  in `packages/cli/src/commands/export.ts`.
- The judge-side transport (`transport.ts`, `presets.ts` in `packages/judge-jev`) is the closest
  example of registration through `defineAdapter`.
- `packages/export-vitest/package.json` follows the J0 dependency-budget template:
  `dependencies: {"@vetkit/spec": "workspace:^"}`, `peerDependencies: {"vitest": "^5.0.2"}`,
  `devDependencies: {"evalite": "1.0.0-beta.16"}` (exact pin, per `docs/contracts/j0.md`
  "Dependency budget").
- The Lock shape that "Edge cases" depends on (`status: 'uncalibrated'`) is fixed in
  `docs/contracts/j0.md` (`criteria.lock.json` has an integer `lockVersion`, ...): lock `status` is
  one of `calibrated`/`floating`, plus `uncalibrated` per criterion via `vet criteria revalidate`.
  The exact shape beyond that is not pinned in a separate J3 contract.
- Evalite's real `createScorer` signature is `createScorer<I,O,E>({name, description,
  scorer:({input, output, expected}) => number})`: its `scorer` function returns a plain `number`,
  not `Promise<{score, metadata}>`. The emitted scorer shape below specifies a richer async
  `{score, metadata}` return, so "Evalite-compatible" means shape-adjacent (same `{name, scorer}`
  factory pattern), not a literal signature match.

## Why

The library never owns the runner; it emits native scorer files that teams execute unchanged.
Vitest is the first target. This contract fixes the port, the file shapes and the parity rule so
later exporters copy it.

## Context

The judge runner provides `runCase(config, case, criteria, lock)` in
`packages/core/src/judge/run.ts` and the verdict cache; the Lock comes from the J3 contract.
Consumer: a vitest project that imports `@vetkit/core` and the configured judge from its own
`vetkit.config.ts`. The emitted test file imports scorers by relative path and cases from
`evals/cases/*.jsonl` at test time.

## Ports (`packages/spec/src/ports/exporter.ts`)

```
specVersion: 'v1'
id: 'vitest'
doExport({criteria, cases, lock, outDir}) → Promise<{files: string[]}>
```

Adapters register through `defineAdapter` and a spec-version mismatch throws `VetError` with code
`E_ADAPTER_SPEC_VERSION` at registration. The registration test asserts
`VetError.code === 'E_ADAPTER_SPEC_VERSION'`.

Verify: `packages/spec/src/ports/exporter.test-d.ts` type test and one registration test.

## Emitted file shapes

- `<outDir>/scorers/<criterionId>.ts` exports `createScorer()` returning `{ name: string, scorer:
  (args:{input:string, output:string, expected?:unknown}) => Promise<{score:number,
  metadata:{criterionId, wordingHash, model:{requested,resolved,transport,pinned}, status,
  probability?, threshold?}}> }` (Evalite-compatible shape).
- `<outDir>/<criteriaFile>.evals.test.ts`: one `describe` per criteria file, one `test` per case,
  asserting `score >= 1` when `pass` and `< 1` otherwise, and `test.skip` with the status name
  when the lock marks the criterion uncalibrated.

`model` in the emitted metadata reuses `JudgeResponse.model`'s field names
(`requested`/`resolved`/`transport`/`pinned`) fixed in `docs/contracts/j1.md` "Ports" — this
contract defines no new model-identity shape. `wordingHash` and `criterionId` reuse
`Criterion.wordingHash`/`Criterion.id` from `docs/contracts/j1.md` "IR".

Verify: `packages/export-vitest/src/emit-scorer.test.ts` and `emit-test.test.ts` compile the
emitted files with `bun run typecheck` in a temp workspace.

## Parity rule

For every case, vitest pass/fail equals `vet run --json` pass/fail (same lock, same judge, cache
shared via `.vet/cache`).

Verify: `vet export --to vitest && bun x vitest run --reporter=json evals/vitest >
/tmp/vt.json && vet run --json > /tmp/run.json && node scripts/diff-verdicts.mjs /tmp/run.json
/tmp/vt.json` → 0 differences, exit 0.

The cache key and `.vet/cache` location are fixed in `docs/contracts/j1.md` "Cache key" —
`sha256(state, wordingHash, model.resolved)`; this contract adds no new cache mechanism, it only
requires the emitted scorer to share that cache with `vet run`.

## Error codes

`EXPORT_NO_LOCK` (lock missing and `--require-lock`), `EXPORT_TARGET_UNKNOWN` (`--to promptfoo` →
exit 2 listing registered exporters). Both are added to `packages/spec/src/errors.ts`, following
the additive pattern `docs/contracts/j1.md` "Error codes" uses for its own new codes (none of the
existing 22 removed). Both apply to `vet export --to <target> [--out evals/vitest]
[--require-lock]` and map to exit 2.

Verify: `bun x vitest run packages/cli/src/errors.test.ts` asserting `EXPORT_NO_LOCK` and
`EXPORT_TARGET_UNKNOWN` → exit 2.

## Scope

IN: port, two emitters, the CLI subcommand, the diff script, the end-to-end gate. OUT:
Promptfoo/pytest/plugin-eval exporters, Evalite runtime integration beyond shape compatibility,
watch mode.

## Approach

Add `packages/spec/src/ports/exporter.ts`, `packages/export-vitest` (scorer and test emitters),
and `vet export` in `packages/cli/src/commands/export.ts`. Closest example: `packages/judge-jev`
registration via `defineAdapter`.

## Edge cases

Lock absent (scorers still emitted; tests run with threshold 0.5 and `metadata.status:
'uncalibrated'` unless `--require-lock`); a case whose trace is `content_not_captured` (`test.skip`
with the status); judge unscored at test time (test fails with the cause, never a silent pass).

`content_not_captured` is one of `Verdict.status`'s enumerated values fixed in
`docs/contracts/j1.md` "IR" — this contract adds no new status value. The default threshold
`0.5` matches `thresholds.default` in the `vetkit.config.ts` schema, not a value this contract
itself introduces.

## Design notes

- First export target is Vitest (scorer module + `.test.ts` generation, Evalite-compatible scorer
  shape); Promptfoo, pytest and Claude plugin-eval are later exporters behind the same exporter
  interface.
- The Evalite-compatible `{name, scorer}` shape is used because every runner converges on
  Case→Scorer→{score, metadata}, and vitest is the chosen first target. The emitted scorer calls
  the real judge at test time through `@vetkit/core` (real data only; no mock in a shipped path).
  Exporters are adapters that import only spec.
- Three further deliverables belong to the J4 journey: a JUnit reporter, a GitHub Action, and the
  `@vetkit/scorers` judge-only package (Braintrust/Evalite/autoevals scorer, promptfoo javascript
  assertion, vitest matcher). The end-to-end gate also requires them. No acceptance criteria or
  verify command is defined for these three here; each owns only the files listed under "Enforced
  by".

## Verification

The contract is done when the port type test passes and the file-shape test compiles emitted
output; parity is proven by the end-to-end gate.
