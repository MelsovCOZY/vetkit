# J0 contract: repository, package and script contract

Status: reference for the repository, package and script layout that every later package builds
against; it is enforced by the tests and scripts named in "Enforced by" below.

## Toolchain versions

Toolchain versions the contract was written against: `bun --version` → `1.4.2`;
`node --version` → `v22.23.2`; `npm --version` → `10.9.8`.

## Packages

Eleven packages exist, all version `0.0.0`, all ESM-only:

- `packages/spec`
- `packages/core`
- `packages/cli`
- `packages/judge-jev`
- `packages/generator-openai-compatible`
- `packages/source-jsonl`
- `packages/source-otlp`
- `packages/source-langfuse`
- `packages/sink-otel`
- `packages/sink-langfuse`
- `packages/export-vitest`

Architecture: three-tier split. `@vetkit/spec` is the
JSON Schema 2020-12 IR as source of truth (generated TS types, spec-version literals, Symbol.for
registry). `@vetkit/core` is the generate → lint → validate → run → export pipeline (event
emitter). Adapters (`source-*`, `judge-*`, `sink-*`, `export-*`) import **only** `@vetkit/spec`,
never `@vetkit/core`. Every adapter object carries `specVersion` + `capabilities`; a mismatch
throws a named error at registration, never a silent no-op. Adapters take injected vendor
clients (Kysely style); vendor SDKs are optional peers. The judge contract is structurally
compatible with the AI SDK `EvaluationModel` but is vetkit's own `JudgeV1`. Standard Schema is
accepted only at the TS authoring edge and converted to JSON Schema immediately. `defineConfig`
takes explicit adapter objects; the config file is imported by Node itself, and string/`file://`
references are resolved only in the Node-only CLI entry. ESM-only,
`engines.node ^22.18.0 || >=24.11.0`, no top-level await, Node CI matrix 22/24/26. `criteria.lock.json` has an integer `lockVersion`, content hashes of questions and
dataset, requested vs observed model, per-question fitted thresholds. Results are cached by
(input hash, wording hash, versioned model id).

## Naming

npm scope `@vetkit/*` (unscoped `vetkit` was free on npm: registry 404 probed 2026-09-25). CLI
package name `vetkit`, bin name `vet`. Config file `vetkit.config.ts`. Cache dir `.vet/`.
Renaming is a `package.json`-only change.

## Package manifest template

Every `packages/<name>/package.json` declares:

- `name`: `@vetkit/<name>` (the `cli` package is named `vetkit`, bin `vet`)
- `version`: `0.0.0`
- `type`: `module`
- `sideEffects`: `false`
- `engines.node`: `"^22.18.0 || >=24.11.0"`
- `files`: `["dist"]`
- `exports`: a map whose every entry has **only** `types` and `import` conditions pointing into
  `dist` — no `main`, no `require`, no `bun` condition. Template per package:
  ```json
  {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" }
  }
  ```
  plus one entry per documented subpath, and `./package.json` exported.
- `publishConfig.access`: `public`

A package added later without following this template must fail `scripts/manifests.test.ts` —
that test globs `packages/*/package.json`, it does not hard-code the package list.

Node-behaviour edge cases: a consumer on Node 22.17 or 24.10 gets an `engines` warning, not a
runtime crash. `require()` of a package from CJS works via `require(esm)` on every Node in that
range — no `require` condition is added to fake support for older Node.

In-monorepo source resolution uses a custom `@vetkit/source` condition in tsconfig
`customConditions` only; it is never published.

## Toolchain roles

Bun 1.4.x is the runtime for dev, the package manager (workspaces, `catalog:`/`workspace:`
protocols, isolated installs, text `bun.lock`), the script runner, and the packer (`bun pm
pack`). Bun is **not** the build of record (no `.d.ts` emit, experimental CJS), **not** the
gating test runner (cannot prove Node behaviour), and **not** the publisher (no `--provenance`,
no OIDC).

- Build: `tsdown` (dts through oxc under `isolatedDeclarations`, `publint`+`attw` built in)
- Typecheck: TypeScript 7 `tsc --noEmit` (TS 6 only inside the consumer matrix)
- Tests: `vitest` with `.test-d.ts` type tests
- Type-perf budget: `tsc --extendedDiagnostics` instantiation count, fail on >20% regression
- Commit style: PR-title conventional-commit check
- Versioning: `changesets` (version + changelog only)
- Publish: `bun pm pack` → tarball checks → `npm publish <tgz>` under OIDC trusted publishing —
  **never** `bun publish`, **never** `changeset publish`
- Package validation (on the packed tarball): `publint --strict`, `arethetypeswrong
  --profile esm-only`, `knip --production`, `validate-package-exports`
- PR previews: `pkg-pr-new`
- Dependency bot: Renovate
- CLI parsing: `commander@15`
- Prompts/color: `@clack/prompts` + `picocolors` (or `util.styleText`)
- API snapshots: `tsnapi`
- `AGENTS.md` maintained

Caveat: `bun pm pack` takes internal versions from `bun.lock` — a stale lockfile ships wrong
versions. Mitigated by `scripts/pack.ts`'s version-sync check and the frozen-lockfile
install in CI.

## Code conventions

Erasable syntax only — no `enum`, no `namespace`, no parameter properties, no decorators;
`as const` objects + derived unions (the IR codegen emits the same). No import cycles. No
internal barrels — one explicit named-re-export `src/index.ts` per package, no `export *`.
Top-level `import type`. `interface` for object shapes, `type` for unions, property-style method
signatures. Factories + interfaces exported, no exported classes except errors. Errors carry a
`Symbol.for` marker + string `code` + `cause` + `static isInstance`, never `instanceof` across
packages. Expected failures are discriminated-union data
(`{status: 'ok'|'unscored'|'error'|...}`), throw only for config/programmer errors. One
`safeParseJson(text, schema)` chokepoint in `spec`, raw `JSON.parse` banned by CI grep. IR uses
JSON-native types only, dates as ISO strings. `noExplicitAny` and `noNonNullAssertion` at error.

tsconfig base: `module` node20, `target` es2023, `strict`, `verbatimModuleSyntax`,
`isolatedModules`, `erasableSyntaxOnly`, `isolatedDeclarations`, `rewriteRelativeImportExtensions`
(write `./x.ts`), `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
`declaration`+`declarationMap`, `rootDir` `src`, `outDir` `dist`, `types` `["node"]` (never `bun`
in the declaration-emitting config).

## JSON Schema validation

`ajv@8` in 2020-12 mode is the single runtime dependency of `@vetkit/spec` and backs
`safeParseJson(text, schema)`. `yaml@2` is `core`'s only runtime dependency (`criteria.yaml`).
Rationale: the IR is JSON Schema 2020-12 and `ajv` is the only maintained
validator with full 2020-12 support; a hand-written validator would be a second source of truth.

## Primitives every later package depends on

Exported from `@vetkit/spec`:

- `VetError` — `Symbol.for` marker, `code`, `cause`, `static isInstance`
- `safeParseJson(text, schema)`
- `SPEC_VERSION === 'v1'`
- `defineAdapter()`

## Scope

In scope: the contract text above, encoded as acceptance criteria. Out of scope: behaviour of
the packages; publishing itself (a workflow is defined, a human triggers it); CLI flags beyond
`--version`.

## Verification (this contract, as a whole)

`bun run check && bun run build && bun run pack` exit 0; `bun x vitest run scripts/` exit 0; CI
green on the consumer matrix.

## Enforced by

| Criterion | Enforced by |
|---|---|
| Package manifest shape (name, version, `type`, `sideEffects`, `engines.node`, `files`, `exports`, `publishConfig`) for all 11 packages | `scripts/manifests.test.ts` — `bun x vitest run scripts/manifests.test.ts` exit 0 |
| Root scripts (`typecheck`, `lint`, `fmt`, `test`, `build`, `pack`, `check`) exist and exit 0 on a green tree | `bun run check && bun run build && bun run pack; echo $?` prints 0 |
| CI consumer imports resolve for every package/exports entry on the packed tarball | `scripts/consumer-matrix.sh` exit 0 in the CI workflow |
| Adapters import only `@vetkit/spec`, never `@vetkit/core` | `scripts/lint-config.test.ts` — `bun run lint` exit 1 on a fixture file that imports `@vetkit/core` from an adapter package |
| Dependency budget (spec: 1 runtime dep; core: 1 runtime dep; adapters: ≤1 optional peer each; no `ai`/`@types/bun`/`bun-types`) | `scripts/manifests.test.ts` |
| `VetError`, `safeParseJson`, `SPEC_VERSION`, `defineAdapter` exported from `@vetkit/spec` | `bun x vitest run packages/spec` exit 0 |
