# J7 contract: vet watch (sampling, inclusion chain, promotion)

Status: reference. This document is the contract for `vet watch` (sampler, inclusion log, promotion
path, exit behaviour); it changes no code itself and is enforced by the tests named in "Enforced by"
below.

## Existing behaviour relied on

- The J5 receiver: `startReceiver(opts): Promise<Receiver>` (`packages/source-otlp/src/receiver/index.ts`)
  resolves `{port, close}` and rejects with the raw Node `error` event from `server.listen`
  (e.g. `EADDRINUSE`); it does not itself wrap a bind failure into a `VetError`. That module's own
  header comment says port/bind handling lives in the CLI, not there. The CLI's `receiverSource`
  (`packages/cli/src/commands/init-otlp.ts`) also awaits `startReceiver` with no try/catch. So no
  existing code wraps a receiver bind failure into a `VetError`; the `RECEIVER_BIND` wrapping
  required by "Exit behaviour" is new work in `vet watch`, not a reuse of J5 code.
- Error codes: `CEV_ERROR_CODES` (`packages/spec/src/errors.ts`) holds the twelve `E_*` codes, the
  J1/J3/J6/J2/J5 unprefixed codes through `RUN_NOT_FOUND` and the Langfuse sink/source codes, plus
  `RECEIVER_BIND` and `WATCH_CONFIG` (see "Error codes"). `packages/cli/src/errors.ts` maps codes to
  exit codes through its `CONFIG_EXIT_CODES` / `INTERNAL_EXIT_CODES` / `INPUT_EXIT_CODES` sets; new
  codes need exact entries there, the same pattern used in the J5 contract
  for `SOURCE_EMPTY`/`OTLP_PARSE`.
- `packages/cli/src/program.ts` prints, in the CLI's shared `--help` text: "the first SIGINT to
  `vet watch` stops it with exit code 0". "Exit behaviour" fixes the full behaviour (drain-once,
  second-SIGINT, receiver-bind exit 2) in one place.
- The core outbox: `Outbox { enqueue(verdicts), drain(sinks), reconcile(opts?) }`
  (`packages/core/src/outbox/outbox.ts`); `drain(sinks: readonly SinkV1[]): Promise<DrainResult[]>`
  drains everything currently pending against the named sinks in one call. This is exactly the
  primitive "the first SIGINT drains the outbox once" needs: the watch loop calls `drain` once on
  first SIGINT, and no new outbox method is required. Sink resolution for a set of `--sink` names
  already exists (`packages/cli/src/sinks.ts`, used by `vet run --sink`), so the watch loop reuses
  it.
- `run-record.ts` (`packages/core/src/run-record.ts`) persists the last `vet run`'s result at
  `<cacheDir>/runs/latest.json` via temp-file-then-rename. `vet watch` defines no persisted record,
  only a printed `{seen, sampled, judged, promoted, produced, acknowledged}` coverage summary on
  exit, so this convention is not reused.
- Cases: `loadCases(dir)` (`packages/core/src/cases/load.ts`) lists `dir` with
  `readdir(dir, {withFileTypes:true})` and keeps only `entry.isFile()` names ending `.jsonl`; it does
  **not** recurse into subdirectories. `vet run`'s default cases dir is `evals/cases`
  (`packages/cli/src/commands/run.ts`). So a file written under `evals/cases/pending/` is already,
  mechanically, invisible to `loadCases('evals/cases')`: "pending files are not read by `vet run`"
  holds with no extra filtering logic, as a direct consequence of `loadCases` being non-recursive.
- `Case.provenance` is typed `unknown`: `packages/spec/schemas/case.schema.json` has
  `"provenance": {}` (an open schema) and the generated `packages/spec/src/generated/case.ts` types
  it `provenance: unknown`. `PromotedCase extends Case { provenance: Case['provenance'] & {
  promotedFrom: {...} } }` therefore reduces, under real TypeScript semantics (`unknown & T`
  simplifies to `T`), to `provenance: { promotedFrom: {...} }`; there is no existing provenance
  shape to intersect with. The type test asserts that reduced, literal shape, not the unreduced
  intersection.
- `.vet/` is the established default cache-dir convention: `DEFAULT_CACHE_DIR = '.vet'`
  (`packages/core/src/config.ts`), already used for `.vet/junit.xml`
  (`packages/cli/src/reporters/junit.ts`) and `.vet/cache` (`packages/core/src/judge/cache.ts`).
  `WatchOptions.inclusionPath`'s default `.vet/watch/inclusion.jsonl` follows this convention.

## Why

The last eval journey is online. A team leaves `vet watch` running against its collector; a
deterministic sample of live traces is judged; results go back through the unsampled outbox (J6);
every failing trace becomes a regression case automatically, gated behind human review before it
counts. OpenTelemetry is in scope in both directions (the consume half is J5/J7; the emit half is
J6, `docs/contracts/j6.md`). The design is thin: one sampler, one loop, one promotion path.

## Context

Consumer: the developer at the terminal, or a long-running process in CI or a sidecar. Inputs: a
`NormalizedTrace` stream from the J5 receiver (`createOtlpReceiver({port}).doRead()` yields as
spans arrive; see "Existing behaviour relied on" for `startReceiver`), criteria + lock from the
project (J1/J3), sinks + outbox (J6, reused as-is).

Package layout is fixed by "Layout" below; this contract fixes only the shapes that the sampler, the
loop, the promotion path and `vet cases review` share.

## Ports and types

`packages/core/src/watch/types.ts`:

```ts
interface WatchOptions {
  sampleRate: number /* 0..1 */;
  upstreamSampleRate?: number;
  maxInFlight: number /* default 4 */;
  promoteOn: 'fail' | 'never' /* default 'fail' */;
  inclusionPath: string /* .vet/watch/inclusion.jsonl */;
  promotedDir: string /* evals/cases — promoted lines are written under <promotedDir>/pending/ */;
}

interface InclusionRecord {
  traceId: string;
  at: string /* ISO */;
  sampled: boolean;
  reason: 'rate' | 'filtered:incomplete' | 'filtered:no_content';
  evaluatorRate: number;
  upstreamRate: number | 'unknown';
  inclusionProbability: number | 'unknown';
}

interface PromotedCase extends Case {
  provenance: Case['provenance'] & {
    promotedFrom: { traceId: string; criterionId: string; verdictId: string; at: string };
  };
}
```

Because `Case['provenance']` is `unknown`, `PromotedCase['provenance']` typechecks as exactly
`{ promotedFrom: { traceId: string; criterionId: string; verdictId: string; at: string
} }`; `types.test-d.ts` asserts this reduced shape, not the unreduced intersection.

## Layout

`packages/core/src/watch/{types,sampler,loop,promote}.ts`; `packages/cli/src/commands/watch.ts`.
The types, their type test and `docs/watch.md` are covered directly by this contract; see "Scope".

## Sampling rule

`sampled` iff `hashToUnit(traceId) < sampleRate`, where `hashToUnit` = the first 8 bytes of
`sha256(traceId)` read as a big-endian `uint64`, divided by 2^64 — deterministic across restarts
and processes (no in-memory random state to lose). Traces whose completeness flags (J5,
`docs/contracts/j5.md` "Completeness → Verdict.status") exclude content-dependent criteria are
recorded with `reason: 'filtered:incomplete'` or `'filtered:no_content'` and are not judged, never
counted as sampled.

Edge cases: `sampleRate: 0` records everything with `sampled: false` (a dry run that still writes
the inclusion chain); `sampleRate: 1` judges everything. When `upstreamSampleRate` is given,
`inclusionProbability = upstreamSampleRate × evaluatorRate`; otherwise `upstreamRate` and
`inclusionProbability` are both `'unknown'` (the OTLP payload carries no observable upstream
ratio; see "Design choices") and any coverage report built from the inclusion log must label the
result a biased sample rather than a population estimate.

## Inclusion log

One `InclusionRecord` JSON object per line, appended to `WatchOptions.inclusionPath` (default
`.vet/watch/inclusion.jsonl`, following the existing `.vet/` cache-dir convention).
Every trace the receiver yields gets exactly one line, sampled or not, judged or filtered: the log
is the full sampling chain (SDK ratio × tail policy × evaluator rate × filters), not
only the sampled subset.

## Promotion

A verdict with `pass: false` and `status: 'ok'` appends one `PromotedCase` line to
`evals/cases/pending/promoted-<YYYY-MM-DD>.jsonl` (one file per UTC day), `id:
promoted-<traceId>-<criterionId>`, never duplicated within a file. `promoteOn: 'never'` disables
this entirely (no pending files written). Pending files are never read by `vet run`; this is a
direct consequence of `loadCases` not recursing into subdirectories of `evals/cases`, not new
filtering logic. A human moves lines into `evals/cases/promoted-<date>.jsonl` (or a quarantine
file) with `vet cases review`, so an auto-promoted case never counts toward a gate until
reviewed.

## Exit behaviour

`vet watch` is the one documented exception to the CLI-wide "SIGINT → 130" rule,
because stopping a long-running watch is
its normal end, not an interruption:

- **First SIGINT**: drains the outbox once (one `Outbox.drain(sinks)` call), prints
  the coverage summary `{seen, sampled, judged, promoted, produced, acknowledged}`, exits `0`.
- **Second SIGINT** before that drain finishes: exits `130` immediately (the CLI-wide rule
  re-asserts itself once the operator has asked twice).
- **Receiver bind failure** (e.g. port already in use): exits `2` with `VetError RECEIVER_BIND`,
  the error message naming the port. No existing code wraps this failure; the
  code that builds `packages/cli/src/commands/watch.ts` owns the wrapping (see "Scope"). The
  `RECEIVER_BIND`/`WATCH_CONFIG` entries in `packages/spec/src/errors.ts` and
  `packages/cli/src/errors.ts` already exist.

## `vet watch` option table

| Flag | Default | Meaning |
|---|---|---|
| `--sample <rate>` | — (required) | `WatchOptions.sampleRate`, 0..1. Outside that range throws `WATCH_CONFIG`. |
| `--port <n>` | `4318` | Receiver port (J5 `startReceiver`'s `port`). |
| `--max-in-flight <n>` | `4` | `WatchOptions.maxInFlight`: concurrent judge calls in flight. |
| `--no-promote` | promotion on | Sets `WatchOptions.promoteOn = 'never'`. |
| `--json` | off | One JSON coverage-summary document on stdout instead of the human-readable form (CLI-wide `--json` convention, `packages/cli/src/program.ts`). |

## Error codes

Existing codes this contract relies on unchanged: `SOURCE_EMPTY`, `OTLP_PARSE`,
`OTLP_UNSUPPORTED_CONTENT_TYPE` (J5, receiver/reader failures upstream of the sampler);
`SINK_REJECTED`, `SINK_UNREACHABLE`, `SINK_AUTH`, `SINK_PAYLOAD_TOO_LARGE`, `OUTBOX_CORRUPT` (J6,
the drain-once call on first SIGINT can surface any of these).

Codes this contract adds to `CEV_ERROR_CODES`:

- `RECEIVER_BIND` — the receiver failed to bind its port (e.g. `EADDRINUSE`); exit 2, message
  names the port. `packages/spec/src/errors.ts` `CEV_ERROR_CODES` (J7 comment block); exact-entry
  exit-2 mapping in `packages/cli/src/errors.ts`'s `INPUT_EXIT_CODES`.
- `WATCH_CONFIG` — `sampleRate` outside `0..1`; exit 2. Same two files, same entries.

## Edge cases

`sampleRate: 0` → everything recorded `sampled: false` (dry run, useful for validating the
inclusion log's shape before judging anything). `sampleRate: 1` → everything judged.
`upstreamSampleRate` given → `inclusionProbability = upstreamSampleRate × evaluatorRate`; else
`'unknown'`.

## Scope

IN: `types.ts` + its type test, `docs/watch.md`, the option table
above (`--sample <rate>`, `--port <n>` default 4318, `--max-in-flight <n>`, `--no-promote`,
`--json`), and the `RECEIVER_BIND` / `WATCH_CONFIG` entries in `packages/spec/src/errors.ts` (+
`errors.test.ts`) and `packages/cli/src/errors.ts` (+ `errors.test.ts`). Both codes are added to
`CEV_ERROR_CODES` and to `packages/cli/src/errors.ts`'s `INPUT_EXIT_CODES` exact-entry set (same
pattern as J5's `SOURCE_EMPTY`/`OTLP_PARSE`).

OUT: `packages/core/src/watch/sampler.ts`, `packages/core/src/watch/loop.ts`,
`packages/core/src/watch/promote.ts` and `packages/cli/src/commands/watch.ts`, including the
`VetError RECEIVER_BIND` / `WATCH_CONFIG` throw sites (the codes exist, but wiring them into the
receiver-bind and `--sample` validation paths belongs to the watch command, since neither
`packages/source-otlp/src/receiver/index.ts` nor the CLI's existing `receiverSource` in
`init-otlp.ts` wraps a bind failure into a `VetError`); sinks and the outbox (J6); the receiver
(J5); any reweighted population statistics beyond the inclusion probability; `vet cases review`
itself.

## Design choices

- OpenTelemetry is in scope in both directions (online: sample live traces, judge, write back).
  Record the full sampling chain and reweight by inclusion probability or label the result biased;
  keep the evaluator's own sampling and write results through the unsampled durable outbox.
- The live source is the J5 OTLP receiver (:4318). The design is thin: one sampler, one loop, one
  promotion path.
- Promotion: one file per day under `evals/cases/pending/`, id
  `promoted-<traceId>-<criterionId>`; pending cases are excluded from `vet run` until reviewed
  with `vet cases review`.
- SIGINT exception: the first SIGINT to `vet watch` exits 0 (normal stop), the second exits 130;
  every other command exits 130.
- Caveat: upstream SDK/tail sampling ratios are not observable from OTLP payloads; the chain records
  `upstream: 'unknown'` unless the config declares `watch.upstreamSampleRate`, and the coverage
  report labels the estimate "biased sample" in that case.
