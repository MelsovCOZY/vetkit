## Why

Root journey J7: the last eval journey is online. A team leaves `vet watch` running against its
collector; a deterministic sample of live traces is judged; results go back through the unsampled
outbox (J6); every failing trace becomes a regression case automatically, gated behind human
review before it counts. Implements DECISION: OpenTelemetry is in scope in BOTH directions
(consume half is J5/J7; emit half is J6, `docs/contracts/j6.md`). Root design J7 is THIN: one
sampler, one loop, one promotion path.

## Context

Consumer: the developer at the terminal, or a long-running process in CI or a sidecar. Inputs: a
`NormalizedTrace` stream from the J5 receiver (`createOtlpReceiver({port}).doRead()` yields as
spans arrive — see Premise on `startReceiver`), criteria + lock from the project (J1/J3), sinks +
outbox (J6, reused as-is per Premise).

Package layout is fixed by "Layout" below; this contract fixes only the shapes the three leaves
(dh8.1–.3) and `vet cases review` (p4a.1) share.

## Ports and types (verbatim from the payload)

`packages/core/src/watch/types.ts`:

```ts
interface WatchOptions {
  sampleRate: number /* 0..1 */;
  upstreamSampleRate?: number;
  maxInFlight: number /* default 4 */;
  promoteOn: 'fail' | 'never' /* default 'fail' */;
  inclusionPath: string /* .vet/watch/inclusion.jsonl */;
  promotedDir: string /* evals/cases — promoted lines are written under <promotedDir>/pending/ */;
}

interface InclusionRecord {
  traceId: string;
  at: string /* ISO */;
  sampled: boolean;
  reason: 'rate' | 'filtered:incomplete' | 'filtered:no_content';
  evaluatorRate: number;
  upstreamRate: number | 'unknown';
  inclusionProbability: number | 'unknown';
}

interface PromotedCase extends Case {
  provenance: Case['provenance'] & {
    promotedFrom: { traceId: string; criterionId: string; verdictId: string; at: string };
  };
}
```

Per Premise, `Case['provenance']` is `unknown` today, so `PromotedCase['provenance']` typechecks
as exactly `{ promotedFrom: { traceId: string; criterionId: string; verdictId: string; at: string
} }` — the type test (dh8.2) asserts this reduced shape, not the unreduced intersection.

## Sampling rule

`sampled` iff `hashToUnit(traceId) < sampleRate`, where `hashToUnit` = the first 8 bytes of
`sha256(traceId)` read as a big-endian `uint64`, divided by 2^64 — deterministic across restarts
and processes (no in-memory random state to lose). Traces whose completeness flags (J5,
`docs/contracts/j5.md` "Completeness → Verdict.status") exclude content-dependent criteria are
recorded with `reason: 'filtered:incomplete'` or `'filtered:no_content'` and are not judged, never
counted as sampled.

Edge cases: `sampleRate: 0` records everything with `sampled: false` (a dry run that still writes
the inclusion chain); `sampleRate: 1` judges everything. When `upstreamSampleRate` is given,
`inclusionProbability = upstreamSampleRate × evaluatorRate`; otherwise `upstreamRate` and
`inclusionProbability` are both `'unknown'` (the OTLP payload carries no observable upstream
ratio — RISK, see Decisions) and any coverage report built from the inclusion log must label the
result a biased sample rather than a population estimate (STATS-2, ONLINE-1).

## Inclusion log

One `InclusionRecord` JSON object per line, appended to `WatchOptions.inclusionPath` (default
`.vet/watch/inclusion.jsonl`, fitting the existing `.vet/` cache-dir convention — see Premise).
Every trace the receiver yields gets exactly one line, sampled or not, judged or filtered: the log
is the full sampling chain (SDK ratio × tail policy × evaluator rate × filters, ONLINE-1), not
only the sampled subset.

## Promotion

A verdict with `pass: false` and `status: 'ok'` appends one `PromotedCase` line to
`evals/cases/pending/promoted-<YYYY-MM-DD>.jsonl` (one file per UTC day), `id:
promoted-<traceId>-<criterionId>`, never duplicated within a file. `promoteOn: 'never'` disables
this entirely (no pending files written). Pending files are never read by `vet run` — per
Premise, this is a direct, pre-existing consequence of `loadCases` not recursing into
subdirectories of `evals/cases`, not new filtering logic this contract has to specify. A human
moves lines into `evals/cases/promoted-<date>.jsonl` (or a quarantine file) with `vet cases
review` (`classified-evals-mol-p4a.1`), so an auto-promoted case never counts toward a gate until
reviewed (DECISION, UX brief C11).

## Exit behaviour

`vet watch` is the one documented exception to the CLI-wide "SIGINT → 130" rule
(`classified-evals-mol-uu0`, `classified-evals-mol-43x`) because stopping a long-running watch is
its normal end, not an interruption:

- **First SIGINT**: drains the outbox once (one `Outbox.drain(sinks)` call, per Premise), prints
  the coverage summary `{seen, sampled, judged, promoted, produced, acknowledged}`, exits `0`.
- **Second SIGINT** before that drain finishes: exits `130` immediately (the CLI-wide rule
  re-asserts itself once the operator has asked twice).
- **Receiver bind failure** (e.g. port already in use): exits `2` with `VetError RECEIVER_BIND`,
  the error message naming the port. Per Premise, no existing code wraps this failure today; the
  leaf that builds `packages/cli/src/commands/watch.ts` (OUT of this contract's scope) owns both
  the wrapping and the `RECEIVER_BIND`/`WATCH_CONFIG` entries in `packages/spec/src/errors.ts` and
  `packages/cli/src/errors.ts` (see "Ownership gaps").

## Error codes

Existing codes this contract relies on unchanged: `SOURCE_EMPTY`, `OTLP_PARSE`,
`OTLP_UNSUPPORTED_CONTENT_TYPE` (J5, receiver/reader failures upstream of the sampler);
`SINK_REJECTED`, `SINK_UNREACHABLE`, `SINK_AUTH`, `SINK_PAYLOAD_TOO_LARGE`, `OUTBOX_CORRUPT` (J6,
the drain-once call on first SIGINT can surface any of these).

New codes this contract adds to `CEV_ERROR_CODES` (none exist today — see Premise), named
explicitly as a leaf-bead addition (owner UNVERIFIED against bd; not assigned to dh8.1–.3 or
p4a.1 by the payload's Scope, which lists only `types.ts` + type test + `docs/watch.md` as IN —
see "Ownership gaps"):

- `RECEIVER_BIND` — the receiver failed to bind its port (e.g. `EADDRINUSE`); exit 2, message
  names the port.
- `WATCH_CONFIG` — `sampleRate` outside `0..1`; exit 2.

## Edge cases

`sampleRate: 0` → everything recorded `sampled: false` (dry run, useful for validating the
inclusion log's shape before judging anything). `sampleRate: 1` → everything judged.
`upstreamSampleRate` given → `inclusionProbability = upstreamSampleRate × evaluatorRate`; else
`'unknown'`.

## Decisions (verbatim, from the payload's `design` and `notes`)

- DECISION: OpenTelemetry is in scope in BOTH directions (online: sample live traces, judge,
  write back). `docs/research/2026-09-25-eval-types-programs-otel-brief.md` §4 ONLINE-1: record
  the full sampling chain, reweight by inclusion probability or label the result biased; §5
  conflict 16: keep the evaluator's own sampling and write results through the unsampled durable
  outbox.
- DECISION (resolves OPEN-2, user 2026-09-25): the live source is the J5 OTLP receiver (:4318).
  Root design J7 is THIN: one sampler, one loop, one promotion path.
- DECISION (UX brief C11, 2026-09-26): promotion rule amended — one file per day under
  `evals/cases/pending/`, id `promoted-<traceId>-<criterionId>`; pending cases are excluded from
  `vet run` until reviewed (`classified-evals-mol-p4a.1` `vet cases review`).
- DECISION (review 2026-09-26): SIGINT exception made explicit — first SIGINT to `vet watch`
  exits 0 (normal stop), second exits 130; every other command exits 130. Promotion path is
  `evals/cases/pending/` with `vet cases review` (`classified-evals-mol-p4a.1`).
- RISK: upstream SDK/tail sampling ratios are not observable from OTLP payloads; the chain records
  `upstream: 'unknown'` unless the config declares `watch.upstreamSampleRate`, and the coverage
  report labels the estimate "biased sample" in that case.

## Ownership gaps

- `RECEIVER_BIND` and `WATCH_CONFIG` have no named owner in the payload's Scope (IN is `types.ts`
  + type test + `docs/watch.md` only). Both need exact entries in `packages/spec/src/errors.ts`'s
  `CEV_ERROR_CODES` and in `packages/cli/src/errors.ts`'s exit-code sets (neither the `SINK_`/

  `packages/cli/src/commands/watch.ts` (`j7-1`..`j7-3`, OUT of this contract's scope).
- The wrapping of `startReceiver`'s raw bind-failure rejection into `VetError RECEIVER_BIND` is
  new code: neither `packages/source-otlp/src/receiver/index.ts` nor the CLI's existing
  `receiverSource` in `init-otlp.ts` does this today (Premise). Whichever `j7-*` leaf builds
  `watch.ts` owns it.
