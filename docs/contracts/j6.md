# J6 contract: OTel out and vendor sinks

Status: reference. This document records the contract that slice J6 implements and that every
J6 leaf builds against. It changes no code itself; it is enforced by the tests named in
"Enforced by" below. Facts are copied verbatim from the root epic ledger
(`bd show classified-evals-d4m`) and the bead payload for `classified-evals-mol-1i0`. UNVERIFIED
markers are kept as written where they occur — this document invents none.

## Why

J6 lets `vet run --sink otel,langfuse` land every verdict back on the span it judged, in any
backend, with zero manual id handling. This contract fixes the shapes that the two sink packages,
the outbox and the CLI wiring all consume so the leaves can be built in parallel. Implements
DECISION: OpenTelemetry is in scope in BOTH directions (emit half) and the root acceptance line
J6.

## Port (`packages/spec/src/ports/sink.ts`)

Verbatim from the plan skeleton:

```ts
interface SinkV1 extends AdapterBase {
  capabilities: { batch: number; idempotent: boolean };
  doWrite(
    batch: Verdict[],
    opts: { signal?: AbortSignal },
  ): Promise<{
    accepted: string[];
    rejected: Array<{ id: string; reason: string; retryable: boolean }>;
  }>;
}
```

`Verdict` and `AdapterBase` are reused as-is from `docs/contracts/j1.md` (`Verdict`) and J0/J1's
registry (`AdapterBase`) — this contract defines no new base types, only `SinkV1` and the ack
shape it returns.

## Mapping tables (verbatim, to be put in `docs/sinks.md`)

- **`gen_ai.evaluation.result` LogRecord**: `gen_ai.evaluation.name` = criterionId;
  `gen_ai.evaluation.score.value` = boolean → P(true), score → expected level index, choice →
  credit of the chosen option (1 when chosen == pass option, else 0); `gen_ai.evaluation.score.label`
  = boolean → pass|fail, choice → chosen option, score → legend name; `gen_ai.evaluation.explanation`
  = deterministic string built from the answer (`"<criterionId>: p=0.98 >= threshold 0.70 →
  pass"`); `gen_ai.response.id` = `provenance.responseId` when present; `error.type` =
  `verdict.status` when `status != 'ok'` and NO score attributes; LogRecord context =
  `{ traceId: provenance.traceId, spanId: provenance.spanId }` (hex, as OTLP/JSON requires);
  extension attributes under `classified_evals.*` (judge model resolved id, transport, pinned,
  wordingHash, cacheHit).
- **OpenInference EVALUATOR span**: `openinference.span.kind=EVALUATOR`, exactly ONE span link to
  `{traceId, spanId}`, attributes
  `evaluations.0.evaluation.{name,score,label,explanation,annotator_kind='JEV',identifier=<verdict
  id>}`; never a parent relationship.
- **Langfuse Scores API `POST /api/public/scores`**: `{ traceId, observationId?, name:
  criterionId, value, dataType: boolean → BOOLEAN, choice → CATEGORICAL (stringValue), score →
  NUMERIC, comment: explanation }`; basic auth `base64(pk:sk)`.

The correlation rule: `traceId`/`spanId` come from the evaluated span; fall back to
`gen_ai.response.id` (`provenance.responseId`) when span identifiers are absent. The
judge-failure rule: `error.type` is set and NO score attributes are emitted when
`verdict.status != 'ok'`.

## Error codes

Five codes added to `CEV_ERROR_CODES` (alongside the 22 existing codes, none removed):

- `SINK_REJECTED` — per-item, retryable per sink response.
- `SINK_UNREACHABLE` — network/5xx after retries, retryable.
- `SINK_AUTH` — 401/403, not retryable.
- `SINK_PAYLOAD_TOO_LARGE` — 413 or > 4 MiB batch, split then retry.
- `OUTBOX_CORRUPT` — config error, thrown (not a `doWrite` rejection).

## Scope

the `VetError` sink codes.

OUT: any sink implementation (`classified-evals-mol-yxn.2`..`.5`), the outbox

## Approach (verbatim, as given — see Premise for what is and is not built yet)

Extend `packages/spec/src/ports/` with `sink.ts` following `source.ts`/`judge.ts` (J2/J1)
exactly: interface + `defineSink()` factory that asserts `specVersion` via the registry. Add the
provenance sub-schema to `verdict.schema.json` and re-run `scripts/codegen.ts` (J0 leaf 8) so
`src/generated/verdict.ts` gains the fields. Add the five codes to the `CevErrorCode` union in
`packages/spec/src/errors.ts`. Write `docs/sinks.md` from the tables above.

## Edge cases

A verdict with no `traceId`/`spanId` and no `responseId` cannot be correlated: the ack must
reject it with `reason: 'no correlation id'` and `retryable: false` (the CLI reports it, never
silently drops). Batch larger than the sink's `capabilities.batch` is the outbox's job to split,
not the sink's. A sink that is not idempotent (Langfuse scores create duplicates on retry) must
declare `idempotent: false` so the outbox uses the ack list, not blind retry.

## Decisions (verbatim, from the bead payload's `design` and `notes`)

- DECISION: OpenTelemetry is in scope in BOTH directions: sinks emit `gen_ai.evaluation.result`
  log events parented to the evaluated span + OpenInference EVALUATOR spans + vendor score APIs.
- DECISION: Architecture as presented in the brainstorm: adapters import ONLY spec; every adapter
  carries `specVersion` + `capabilities`.
- DECISION: Code conventions: expected failures are discriminated-union data (rejected items),
  throw only for config errors.
- RISK: OpenAI Evals becomes read-only 2026-10-31: OpenAI Evals is NOT a sink target; Langfuse
  writes go through the Scores API, never trace-level managed evaluators.
- PLAN: PREMISE (web, raw doc fetched 2026-09-25 from github.com/open-telemetry/
  semantic-conventions-genai docs/gen-ai/gen-ai-events.md) — event attributes
  `gen_ai.evaluation.name` (Required), `score.value` (double), `score.label`, `explanation`,
  `gen_ai.response.id`, `error.type`; "SHOULD be parented to GenAI operation span being evaluated
  when possible or set `gen_ai.response.id`".
- PLAN: `docs/research/2026-09-25-eval-types-programs-otel-brief.md` §2 "Emit (EvalResult →
  OTel)" — OpenInference carrier span "MUST have exactly one Span Link to the target",
  "Parentage MUST NOT be used to identify the feedback target"; Langfuse OTel ingest does not
  handle scores.
- RISK: OTel GenAI semantic conventions are Development status — attribute names may be renamed
  before a tagged release; the mapping table pins the semconv commit read on 2026-09-25 and
  records `schema_url`.
- SOURCE: https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-events.md
  — the OTel GenAI SIG spec (vendor-neutral).
- SOURCE: https://github.com/Arize-ai/openinference/blob/main/spec/annotations.md — OpenInference
  annotations spec (Arize maintainers).
- SOURCE: https://langfuse.com/docs/evaluation/scores/overview — Langfuse Scores API, first-party
  docs.
