# J6 contract: OTel out and vendor sinks

Status: reference. This document records the contract for J6 (OTel out and vendor sinks); it changes no
code itself and is enforced by the tests and scripts named in "Enforced by" below.

## Package and CLI facts

- The sink port lives in `packages/spec/src/ports/sink.ts`, alongside `judge.ts`. The generic factory
  `defineAdapter()` in `packages/spec/src/registry.ts` asserts `specVersion` and validates the adapter id
  shape against any `AdapterBase` (`{ specVersion, id, kind, capabilities }`); it is not port-specific.
- `Verdict` (`packages/spec/schemas/verdict.schema.json`, generated into
  `packages/spec/src/generated/verdict.ts`) has `additionalProperties: false`, so adding `provenance`
  is a schema change, not additive-by-default.
- `CEV_ERROR_CODES` in `packages/spec/src/errors.ts` gains five codes from this contract (`SINK_REJECTED`,
  `SINK_UNREACHABLE`, `SINK_AUTH`, `SINK_PAYLOAD_TOO_LARGE`, `OUTBOX_CORRUPT`) on top of the existing
  `E_*` codes and the ten J1 codes (`CONFIG_INVALID`, `CRITERIA_INVALID`, `CASE_INVALID`,
  `JUDGE_UNAVAILABLE`, `JUDGE_TIMEOUT`, `JUDGE_BAD_RESPONSE`, `GATE_REFUSED`, `CACHE_IO`,
  `JUDGE_UNAUTHORIZED`, `INPUT_TOO_LARGE`).
- `packages/cli/src/errors.ts` (`handleError`/`resolveExit`) has a code-list-independent rule: any error
  code whose unprefixed form starts with `SINK_` or `SOURCE_` resolves to `EXIT_SINK_SOURCE_STRICT` (1)
  under `--strict`, or `EXIT_OK` (0) with a warning otherwise. The five new codes need no CLI change for
  the `SINK_*` ones. `OUTBOX_CORRUPT` is a thrown config error, not a `SINK_*`/`SOURCE_*` prefix match, so
  this rule does not cover it; its exit-code bucket is not pinned.
- Packages: `packages/sink-otel/`, `packages/sink-langfuse/` and `packages/source-langfuse/`. Dependency
  budgets follow the J0 contract table: `sink-otel` carries no `@opentelemetry` dependency or peer (it
  hand-encodes OTLP/HTTP JSON over fetch, so users need no OTel SDK); `sink-langfuse` and
  `source-langfuse` each carry `langfuse@^3.39.2` as an optional peer + devDependency.
- Deliverables: `docs/sinks.md`, `e2e/j6.e2e.test.ts` and `scripts/smoke-j6.sh`.

## Why

J6 lets `vet run --sink otel,langfuse` land every verdict back on the span it judged, in any backend,
with zero manual id handling. This contract fixes the shapes that the two sink packages, the outbox and
the CLI wiring all consume so they can be built in parallel. OpenTelemetry is in scope in both
directions (this contract covers the emit half).

## Context

Consumer: the `vet run` command (`packages/cli/src/commands/run.ts`) and the outbox
(`packages/core/src/outbox/`). `@vetkit/spec` has the IR types `Criterion`, `Case`, `Verdict` and the
`AdapterBase`/registry.

## Port (`packages/spec/src/ports/sink.ts`)

Shape:

```ts
interface SinkAck {
  accepted: string[];
  rejected: Array<{ id: string; reason: string; retryable: boolean }>;
}

interface SinkV1 {
  specVersion: 'v1';
  id: string;
  capabilities: { batch: number; idempotent: boolean };
  doWrite(batch: Verdict[], opts: { signal?: AbortSignal }): Promise<SinkAck>;
}

function defineSink(x: SinkV1): SinkV1;
```

`SinkV1` is a standalone port interface with no `kind` field, like `JudgeV1`/`ExporterV1` — it
does not extend the registry's `AdapterBase`. `defineSink()` calls the registry's
`assertSpecVersion()`, passing `kind: 'sink'` only for that call, and does not check the adapter
id shape (sink ids like `otel/logs` contain a slash, which `AdapterBase` ids reject). A
spec-version mismatch throws `E_ADAPTER_SPEC_VERSION`; a bad batch (`capabilities.batch` not a
positive integer) throws `E_ADAPTER_CAPABILITY` — both reuse the existing adapter-validation
codes (the same rule as the J4 `E_ADAPTER_SPEC_VERSION` code), not new sink-specific codes.
`accepted` and each `rejected[].id` are `Verdict.id` values from the batch passed to `doWrite`.
`Verdict` is reused as-is from the J1 contract — this contract defines no new base types,
only `SinkV1`, `defineSink`, and the ack type it returns, `SinkAck`.

## IR additions: `Verdict.id` and `Verdict.provenance`

`Verdict` (J1 IR) must carry:

```ts
id?: string;
provenance: {
  traceId?: string;
  spanId?: string;
  responseId?: string;
  observationId?: string;
  dialect?: string;
  schemaUrl?: string;
}
```

`id` is an optional top-level id: not required, so
J1 verdicts stay valid; the outbox assigns it at enqueue, and it is
what `SinkAck`'s `accepted`/`rejected[].id` refer to.

The sink port work adds these optional fields to
`packages/spec/schemas/verdict.schema.json` (and, via `codegen`, to
`packages/spec/src/generated/verdict.ts`).

## Mapping tables (for `docs/sinks.md`)

- **`gen_ai.evaluation.result` LogRecord**: `gen_ai.evaluation.name` = criterionId;
  `gen_ai.evaluation.score.value` = boolean → P(true), score → expected level index, choice →
  credit of the chosen option (1 when chosen == pass option, else 0); `gen_ai.evaluation.score.label`
  = boolean → pass|fail, choice → chosen option, score → legend name; `gen_ai.evaluation.explanation`
  = deterministic string built from the answer (`"<criterionId>: p=0.98 >= threshold 0.70 →
  pass"`); `gen_ai.response.id` = `provenance.responseId` when present; `error.type` =
  `verdict.status` when `status != 'ok'` and NO score attributes; LogRecord context =
  `{ traceId: provenance.traceId, spanId: provenance.spanId }` (hex, as OTLP/JSON requires);
  extension attributes under `classified_evals.*` (judge model resolved id, transport, pinned,
  wordingHash, cacheHit).
- **OpenInference EVALUATOR span**: `openinference.span.kind=EVALUATOR`, exactly ONE span link to
  `{traceId, spanId}`, attributes
  `evaluations.0.evaluation.{name,score,label,explanation,annotator_kind='JEV',identifier=<verdict
  id>}`; never a parent relationship.
- **Langfuse Scores API `POST /api/public/scores`**: `{ traceId, observationId?, name:
  criterionId, value, dataType: boolean → BOOLEAN (value 0|1), choice → CATEGORICAL (value: the
  choice string), score → NUMERIC (value: expected level), comment: explanation }`; basic auth
  `base64(pk:sk)`.

The correlation rule: `traceId`/`spanId` come from the evaluated span; fall back to
`gen_ai.response.id` (`provenance.responseId`) when span identifiers are absent. The
judge-failure rule: `error.type` is set and NO score attributes are emitted when
`verdict.status != 'ok'`.

## Error codes

This contract adds the five sink codes to `CEV_ERROR_CODES`, none removed:

- `SINK_REJECTED` — per-item, retryable per sink response.
- `SINK_UNREACHABLE` — network/5xx after retries, retryable.
- `SINK_AUTH` — 401/403, not retryable.
- `SINK_PAYLOAD_TOO_LARGE` — 413 or > 4 MiB batch, split then retry.
- `OUTBOX_CORRUPT` — config error, thrown (not a `doWrite` rejection).

## Scope

IN: the `SinkV1` port + ack type, `Verdict.provenance` fields, `docs/sinks.md` mapping tables,
the `VetError` sink codes.

OUT: any sink implementation, the outbox, CLI flags, Phoenix/Datadog/
Braintrust/LangSmith sinks (later work). OpenAI Evals is NOT a
sink target (OpenAI Evals becomes read-only 2026-10-31).

## Approach

Extend `packages/spec/src/ports/` with `sink.ts` following `source.ts`/`judge.ts` (the J2/J1 ports)
exactly: interface + `defineSink()` factory that asserts `specVersion` via the registry. Add the
provenance sub-schema to `verdict.schema.json` and re-run `scripts/codegen.ts` (the J0 codegen script) so
`src/generated/verdict.ts` gains the fields. Add the five codes to the `CevErrorCode` union in
`packages/spec/src/errors.ts`. Write `docs/sinks.md` from the tables above.

## Edge cases

A verdict with no `traceId`/`spanId` and no `responseId` cannot be correlated: the ack must
reject it with `reason: 'no correlation id'` and `retryable: false` (the CLI reports it, never
silently drops). Batch larger than the sink's `capabilities.batch` is the outbox's job to split,
not the sink's. A sink that is not idempotent (Langfuse scores create duplicates on retry) must
declare `idempotent: false` so the outbox uses the ack list, not blind retry.

## Design notes

- OpenTelemetry is in scope in both directions: sinks emit `gen_ai.evaluation.result` log events
  parented to the evaluated span + OpenInference EVALUATOR spans + vendor score APIs.
- Adapters import only spec; every adapter carries `specVersion` + `capabilities`.
- Code conventions: expected failures are discriminated-union data (rejected items); throw only for
  config errors.
- OpenAI Evals becomes read-only 2026-10-31, so it is not a sink target; Langfuse writes go through the
  Scores API, never trace-level managed evaluators.
- OTel GenAI event attributes (from
  https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-events.md):
  `gen_ai.evaluation.name` (Required), `score.value` (double), `score.label`, `explanation`,
  `gen_ai.response.id`, `error.type`; the event "SHOULD be parented to GenAI operation span being
  evaluated when possible or set `gen_ai.response.id`".
- OpenInference: the carrier span "MUST have exactly one Span Link to the target" and "Parentage MUST NOT
  be used to identify the feedback target"; Langfuse OTel ingest does not handle scores.
- OTel GenAI semantic conventions are in Development status, so attribute names may be renamed before a
  tagged release; the mapping table pins the semconv commit read and records `schema_url`. The exact
  commit is not pinned in this document.

## Enforced by

| Criterion | Enforced by |
|---|---|
| Call budget: `vet run --sink otel,langfuse` needs 0 manual trace/span/observation id handling from the user (ids travel inside `Verdict.provenance`); verify: the J6 smoke command passes no id flags | `scripts/smoke-j6.sh`, `e2e/j6.e2e.test.ts` |
| SinkV1 typecheck criterion: developer imports `SinkV1`, `SinkAck`, `defineSink` from `@vetkit/spec` and `Verdict.provenance.traceId` is typed as `string \| undefined`; verify: `bun x vitest run packages/spec/src/ports/sink.test-d.ts` exit 0 | `packages/spec/src/ports/sink.test-d.ts` |
| `docs/sinks.md` mapping-table criterion: every sink (`otel`, `otel-openinference`, `langfuse`) has a field-by-field mapping table, the correlation rule, and the judge-failure rule; verify: `test -s docs/sinks.md && grep -c 'gen_ai.evaluation.name' docs/sinks.md` >= 1 | `docs/sinks.md` |
| Sink error-code criterion: every sink error code (`SINK_REJECTED`, `SINK_UNREACHABLE`, `SINK_AUTH`, `SINK_PAYLOAD_TOO_LARGE`, `OUTBOX_CORRUPT`) exists in `VetError`'s code union; verify: `bun x vitest run packages/spec/src/errors.test.ts -t sink` exit 0 | `packages/spec/src/errors.test.ts` |

End-to-end enforcement of the whole J6 journey is the J6 end-to-end test and smoke script, which pass
only when the port and schema (`sink.ts`, `sink.test.ts`, `verdict.schema.json`), `sink-otel`,
`sink-langfuse`, `source-langfuse`, the outbox and the CLI wiring all work.
