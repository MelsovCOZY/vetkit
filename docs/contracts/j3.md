## Why

Root journey J3: a judge cannot gate anything until it is validated against human labels (ET
brief §2 "Production practice", JEV brief §4 items 5–7). This contract fixes the file formats and
statuses every J3 leaf, J4's scorer emitter and `vet run --gate` depend on. Implements DECISION:

## Context

Consumer: the developer at the terminal and their CI.

Commands (call budget: exactly two — `vet label`, `vet validate` — take a criteria file plus
≥100 labels per criterion to a `criteria.lock.json`):

- `vet label --from labels.csv | --tty` writes `evals/labels/<criterion>.csv`.
- `vet validate [--criteria evals/criteria.yaml] [--labels evals/labels/] [--repeats 3] --json`

## Lock file (`criteria.lock.json` → `packages/spec/schemas/lock.schema.json`)

```ts
interface Lock {
  lockVersion: 1;
  model: {
    requested: string;
    resolved: string;
    transport: string;
    pinned: boolean;
    releaseDate?: string;
  };
  criteria: Record<string, {
    wordingHash: string;
    status: 'calibrated' | 'uncalibrated' | 'floating';
    threshold?: number;
    tpr?: number;
    tnr?: number;
    ece?: number;
    tolerance?: number;
    gauntlet: Record<
      'paraphrase' | 'polarity' | 'injection' | 'master_key' | 'label_permutation'
      | 'constant_output' | 'position_swap' | 'length',
      'pass' | 'fail' | 'skipped'
    >;
    reasons: LockReason[];
    languages?: string[];
    labelCount: number;
  }>;
  datasetHash: string;
}

type LockReason =
  | 'too_few_labels'
  | 'single_class'
  | 'single_class_heldout'
  | 'class_too_small'
  | 'unstable'
  | 'language_limited'
  | 'score_not_gateable'
  | 'reference_missing'
  | 'paraphrase'
  | 'polarity'
  | 'injection'
  | 'master_key'
  | 'label_permutation'
  | 'constant_output'
  | 'position_swap'
  | 'length';
```

The eight gauntlet keys are fixed (DECISION, eval-quality brief applied, 2026-09-26): `paraphrase`
and `polarity` (Gauntlet A, `classified-evals-mol-q4q.4`); `injection`, `master_key`,
`label_permutation`, `constant_output` (Gauntlet B, `classified-evals-mol-q4q.5`); `position_swap`,
`length` (Gauntlet C, `classified-evals-mol-q4q.8`). `label_permutation` is the renamed null model;
`constant_output` is new (item 4). `reasons[]` and `languages[]` are the two enums added by the
same DECISION (items 1, 9).

`model` reuses `JudgeResponse['model']`'s shape from `docs/contracts/j1.md` (`requested`,
`resolved`, `transport`, `pinned`, optional `releaseDate`), minus `provider` — not carried into the
lock by this contract's field list above.

## Labels CSV (`evals/labels/<criterion>.csv`)

Columns: `case_id,criterion_id,label,labeler,labeled_at`. `label ∈ {pass, fail, unknown}`. Rows
with `unknown` are excluded from fitting but counted (toward `labelCount` and toward the
≥100-per-criterion budget, per the description's edge cases).

## Status semantics

A criterion is `calibrated` only when **all** of:

- `labelCount ≥ 100` with `≥30` pass and `≥30` fail rows in the held-out split (else reason
  `class_too_small`, DECISION eval-quality brief item 1).
- Every gauntlet entry is `pass` (a failed `constant_output` gives reason `constant_output`, item
  4).
- TPR/TNR are reported on a held-out split.
- Its type is `boolean` or `choice` (`score` → reason `score_not_gateable` until the JS spike
  measures score, item 14).
- A `factual`/`math`/`code` criterion (`Criterion.checkable`) has a `reference` or `code` grader
  (else reason `reference_missing`, item 11).

`ECE` is reported, never gated. `floating` when the lock's `model.pinned` is `false` (DECISION,
amends pinning, after probe). Anything else is `uncalibrated`.

## Error codes (`VetError.code`)

Four new codes, added to `packages/spec/src/errors.ts`'s `CEV_ERROR_CODES` (none of the existing
20 move):

- `LABELS_TOO_FEW` — `<100` per criterion → exit 2 with the count.
- `LOCK_STALE` — `wordingHash`, `datasetHash` or `model.releaseDate` differs → exit 1 per the root
  exit-code DECISION; a missing lock is exit 2. (DECISION, 2026-09-26, eval-quality application:
  this corrects an earlier "exit 3" in this bead's acceptance text to "exit 1" to match the
  exit-code DECISION and `classified-evals-mol-q4q.6`; stale text only, no behaviour change.)
- `GATE_UNCALIBRATED` — `vet run --gate` names the criterion, exit 2.
- `GATE_UNPINNED` — `vet run --ci` on a floating lock without `--allow-unpinned`, exit 2.

## Gate contract

`vet run --gate` never gates:

- on a `score` criterion — verdict `gated:false`, `gateReason: 'score_not_gateable'`;
- on a verdict for a case whose `Case.language` is outside the criterion's lock `languages[]` —
  `gateReason: 'language_not_calibrated'`.

Both `gateReason` values are already present in `docs/contracts/j1.md`'s `Verdict` type.

## Statistics (owned by `classified-evals-mol-q4q.3`, fixed here as contract)

Per ET brief §2: TPR/TNR are the gate; Cohen κ is the summary statistic for boolean; Krippendorff
α (ordinal) for score. ECE is report-only, never a gate (eval-quality brief §5.2 item 12). ≥100
labels per criterion, split train/dev/test (Husain, cited by the design). Thresholds carry a
tolerance band derived from measured repeat variance (RISK, measured 2026-09-25: score moved
2.78→2.81, confidence 0.26→0.01 on an identical repeat request). Every statistic is computed by
plain arithmetic in `core`; no stats dependency is in the skeleton dependency list (Approach).
Thresholds are on the pass-value scale: P(yes) for boolean, the expected level E for score,
inverted to 1 − p or max − E for `pass_when_false`; `vet run` compares the same value.

Numeric floors fixed by this plan (DECISION, eval-quality brief applied, item list, re-tune after
the JS spike): 30/30 held-out class floor, 0.90 paraphrase decision-agreement, 0.90 position-swap
consistency, κ ≥ 0.60 per-language slice floor, constant-output ≤0.25× real pass rate,
near-duplicate pre-filter Jaccard 0.5.

## Edge cases

- Labels with `unknown` (excluded from fitting, counted toward `labelCount`).
- Criteria with zero fails in labels (TNR undefined → `uncalibrated` with reason).
- A lock written through a floating transport (→ `floating` status per the pinning DECISION).
- Wording edits after locking (→ `LOCK_STALE`).
- Repeats `< 3` (tolerance unavailable → status `uncalibrated`).
