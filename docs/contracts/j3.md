# J3 contract: Validate and calibrate criteria into criteria.lock.json

Status: reference. This document defines the J3 file formats, statuses, error codes and gate behaviour
that `vet label`, `vet validate`, J4's scorer emitter and `vet run --gate` build against; it changes no
code itself and is enforced by the tests named in "Enforced by" below.

## Existing code this contract builds on

- `docs/contracts/j1.md` is the authority for `JudgeV1`, `Criterion`, `Case`, `Verdict`, `Answer`,
  `Model` and the 20 existing error codes; this document reuses those names verbatim and redefines
  none of them.
- `Criterion.checkable`/`grader`, `Case.expected`/`language`/`cluster` and `Verdict.gated`/`gateReason`
  (`'score_not_gateable' | 'language_not_calibrated'`) already exist in
  `packages/spec/src/generated/` and are reused as is.
- `packages/cli/src/errors.ts`'s `resolveExit` checks an exact-match `CONFIG_EXIT_CODES` set (exit 2)
  and `INTERNAL_EXIT_CODES` set (exit 70) first; then prefix rules map `NOT_INTERACTIVE`/`CONFIG*`/`GATE_*`
  to 2, `UNSCORED_ONLY` to 3, `SINK_*`/`SOURCE_*` to 1 strict / 0 warn; anything else falls through to
  exit 70. `GATE_UNCALIBRATED` and `GATE_UNPINNED` already match the `GATE_*` prefix rule (exit 2)
  with no code change. `LABELS_TOO_FEW` and `LOCK_STALE` match no existing rule and would fall through
  to exit 70, so meeting this contract's exit-2/exit-1 requirements for them needs an edit to
  `packages/cli/src/errors.ts` (see "Ownership").

## Why

A judge cannot gate anything until it is validated against human labels. This contract fixes the file
formats and statuses that `vet label`, `vet validate`, J4's scorer emitter and `vet run --gate` depend
on. `criteria.lock.json` is the only artifact that lets a criterion gate anything; pinning is amended
so a lock written through a floating transport is `floating`; and the gauntlets, class floors,
per-language calibration and reference graders below come from the eval-quality work.

## Context

Consumer: the developer at the terminal and their CI.

Commands (call budget: exactly two — `vet label`, `vet validate` — take a criteria file plus
>=100 labels per criterion to a `criteria.lock.json`):

- `vet label --from labels.csv | --tty` writes `evals/labels/<criterion>.csv`.
- `vet validate [--criteria evals/criteria.yaml] [--labels evals/labels/] [--repeats 3] --json`
  writes `criteria.lock.json` and prints the gauntlet report:
  ```
  {
    criteria: [{
      id, status, reasons, languages, byLanguage, threshold, tpr, tnr, se, ece,
      reliability, correctedPassRate, tolerance, gauntlet, detail
    }],
    model,
    datasetHash
  }
  ```
- `vet check --lock` prints `{ stale: boolean, reasons: [] }`.

Library functions:

```ts
validateCriteria(config, { criteria, cases, labels, judge, generator, repeats }) → LockDraft
writeLock(path, LockDraft)
checkLock(path, { criteria, cases, model }) → StaleReport
```

## Lock file (`criteria.lock.json` → `packages/spec/schemas/lock.schema.json`)

```ts
interface Lock {
  lockVersion: 1;
  model: {
    requested: string;
    resolved: string;
    transport: string;
    pinned: boolean;
    releaseDate?: string;
  };
  criteria: Record<string, {
    wordingHash: string;
    status: 'calibrated' | 'uncalibrated' | 'floating';
    threshold?: number;
    tpr?: number;
    tnr?: number;
    ece?: number;
    tolerance?: number;
    gauntlet: Record<
      'paraphrase' | 'polarity' | 'injection' | 'master_key' | 'label_permutation'
      | 'constant_output' | 'position_swap' | 'length',
      'pass' | 'fail' | 'skipped'
    >;
    gauntletDetail?: {
      // failing master_key inputs; ids only, never case text. kind: 'fixed' | 'truncation'
      masterKeyFailed?: { kind: string; caseId: string }[];
      // injection families with at least one flip
      injectionFlips?: { family: string; flips: number; trials: number }[];
    };
    reasons: LockReason[];
    languages?: string[];
    labelCount: number;
  }>;
  datasetHash: string;
  requestFormat?: 'fenced-v1'; // written only when fenced-v1; absent means raw
}

type LockReason =
  | 'too_few_labels'
  | 'single_class'
  | 'single_class_heldout'
  | 'class_too_small'
  | 'unstable'
  | 'too_few_repeats'
  | 'language_limited'
  | 'score_not_gateable'
  | 'reference_missing'
  | 'paraphrase'
  | 'polarity'
  | 'injection'
  | 'master_key'
  | 'label_permutation'
  | 'constant_output'
  | 'position_swap'
  | 'length';
```

The eight gauntlet keys are fixed: `paraphrase` and `polarity` (Gauntlet A); `injection`,
`master_key`, `label_permutation`, `constant_output` (Gauntlet B); `position_swap`, `length`
(Gauntlet C). `label_permutation` is the null model; `constant_output` checks a constant answer
against the real pass rate. `reasons[]` and `languages[]` are the two enums recording why a criterion
is not calibrated and which languages it is calibrated for.

`gauntletDetail` is present only when a `master_key` input or an injection family failed, so a fail is
diagnosable from the lock. `masterKeyFailed` sorts by `kind` then `caseId`; `injectionFlips` sorts by
`family` and lists only families with `flips > 0` (`trials` is the family's trial count). Neither
carries case or payload text. `vet validate --json` mirrors them per criterion as
`detail.master_key.failedInputs` (same `{kind, caseId}`) and `detail.injection.flipped` (same
`{family, flips, trials}`).

`model` reuses `JudgeResponse['model']`'s shape from `docs/contracts/j1.md` (`requested`,
`resolved`, `transport`, `pinned`, optional `releaseDate`), minus `provider` — not carried into the
lock by this contract's field list above.

## Labels CSV (`evals/labels/<criterion>.csv`)

Columns: `case_id,criterion_id,label,labeler,labeled_at`. `label ∈ {pass, fail, unknown}`. Rows
with `unknown` are excluded from fitting but counted (toward `labelCount` and toward the
>=100-per-criterion budget).

## Status semantics

A criterion is `calibrated` only when **all** of:

- `labelCount ≥ 100` with `≥30` pass and `≥30` fail rows in the held-out split (else reason
  `class_too_small`).
- Every gauntlet entry is `pass` (a failed `constant_output` gives reason `constant_output`).
- TPR/TNR are reported on a held-out split.
- Its type is `boolean` or `choice` (`score` → reason `score_not_gateable` until score reliability
  is measured).
- A `factual`/`math`/`code` criterion (`Criterion.checkable`) has a `reference` or `code` grader
  (else reason `reference_missing`).

`ECE` is reported, never gated. `floating` when the lock's `model.pinned` is `false`. Anything else
is `uncalibrated`.

## Error codes (`VetError.code`)

Four new codes, added to `packages/spec/src/errors.ts`'s `CEV_ERROR_CODES` (none of the existing
20 move):

- `LABELS_TOO_FEW` — `<100` per criterion → exit 2 with the count.
- `LOCK_STALE` — `wordingHash`, `datasetHash`, `model.releaseDate`, `transport` or `requestFormat` (absent means `raw`) differs → exits 1; a missing lock is exit 2.
- `GATE_UNCALIBRATED` — `vet run --gate` names the criterion, exit 2.
- `GATE_UNPINNED` — `vet run --ci` on a floating lock without `--allow-unpinned`, exit 2.

## Gate contract

`vet run --gate` never gates:

- on a `score` criterion — verdict `gated:false`, `gateReason: 'score_not_gateable'`;
- on a verdict for a case whose `Case.language` is outside the criterion's lock `languages[]` —
  `gateReason: 'language_not_calibrated'`.

Both `gateReason` values are already present in `docs/contracts/j1.md`'s `Verdict` type.

## Statistics

TPR/TNR are the gate; Cohen κ is the summary statistic for boolean; Krippendorff α (ordinal) for
score. ECE is report-only, never a gate. >=100 labels per criterion, split train/dev/test. Thresholds
carry a tolerance band derived from measured repeat variance (measured: score moved 2.78→2.81,
confidence 0.26→0.01 on an identical repeat request). Every statistic is computed by plain arithmetic
in `core`; no stats dependency is in the skeleton dependency list. Thresholds are on the pass-value
scale: P(yes) for boolean, P(passWhen) = Σ p over the `passWhen` labels for choice, the expected level
E for score, inverted to 1 − p or max − E for `pass_when_false`; `vet run` compares the same value.

Numeric floors (to be re-tuned once score reliability is measured): 30/30 held-out class floor, 0.90
paraphrase decision-agreement, 0.90 position-swap consistency, κ ≥ 0.60 per-language floor,
constant-output ≤0.25× real pass rate, near-duplicate pre-filter Jaccard 0.5.

## Scope

IN: the shapes above, status semantics, error codes, the labels CSV.

OUT: the label UI beyond a TTY loop (no web UI); PPI bias correction (not built);
Python.

## Edge cases

- Labels with `unknown` (excluded from fitting, counted toward `labelCount`).
- Criteria with zero fails in labels (TNR undefined → `uncalibrated` with reason).
- A lock written through a floating transport (→ `floating` status).
- Wording edits after locking (→ `LOCK_STALE`).
- Repeats `< 3` (tolerance unavailable → status `uncalibrated`).
