# J5 contract: OTel in — OTLP traces across dialects

Status: reference. This document defines the OTLP-in (consume) contract of `@vetkit/source-otlp`; it
changes no code itself and is enforced by the tests named in "Enforced by" below.

## Schema alignment

The contract follows the trace IR schema and the shipped ports:

- `packages/spec/src/ports/source.ts` exports `SourceV1` and `defineSource`;
  `packages/spec/src/index.ts` re-exports both, plus the generated `NormalizedTrace`, `Span`,
  `Message`, `MessagePart` types. `defineSource` checks `specVersion` only (no `defineAdapter`, no
  freeze, no marker, no id-shape check).
- `packages/spec/schemas/trace.schema.json` defines the IR:
  - `tokens` is optional and shaped `{input?, output?, total?}` (integers ≥ 0). There is no
    `null`: "no usage seen" is the field being absent.
  - `dialect` is a free `string` in the IR (other sources write their own values, e.g.
    source-jsonl). The five-value enum below is owned by `@vetkit/source-otlp`, not by the schema.
  - `dialectVersion` and `schemaUrl` are optional strings; `completeness
    {contentCaptured, truncated, missingParents}` is required.
  - Message parts are `text {content}`, `tool_call {id?, name, arguments?}`,
    `tool_call_response {id?, response}` and `parse_error {detail}`.
- `packages/spec/schemas/verdict.schema.json` `status` already carries `incomplete_trace`,
  `truncated` and `content_not_captured`, and `provenance` already carries optional `traceId`,
  `spanId`, `dialect`, `schemaUrl`. J5 adds no schema field.
- `packages/source-otlp/` depends only on `@vetkit/spec`. No OTel SDK dependency is needed to read
  OTLP/JSON, and none is added.
- The J5 error codes `OTLP_PARSE`, `OTLP_UNSUPPORTED_CONTENT_TYPE` and `SOURCE_EMPTY` are added to
  `CEV_ERROR_CODES` in `packages/spec/src/errors.ts` (which already has `SOURCE_UNREADABLE` and
  `TRACE_INVALID`).
- `resolveExit` in `packages/cli/src/errors.ts` maps any `SOURCE_*` code to exit 0 with a warning
  (exit 1 under `--strict`) and any unknown code to exit 70. So `SOURCE_EMPTY` → exit 2 and
  `OTLP_PARSE` → exit 2, as required below, need exact entries in that file (see "Ownership gaps").
- The CLI `otlp:` prefix registers through the source-resolution seam of the J2 contract
  (`registerSourcePrefix`; the exact export name is not pinned).

## Why

Traces from any OTel-instrumented app become cases without a vendor in the middle. The dialect zoo
(gen_ai latest and legacy, OpenInference, OpenLLMetry, Vercel) is the reason a normaliser exists at
all. OpenTelemetry is in scope in both directions; this document is the consume half, and the emit
half is the J6 contract (`docs/contracts/j6.md`).

## Context

Consumer: developer at the terminal. Call budget: ONE command.

- File: `vet init --source otlp:<file.json|dir> [--json]` →
  `{cases: n, excluded: {content_not_captured, truncated, incomplete_trace}, dialects: {...}}`
  on stdout with `--json`, and `evals/cases/*.jsonl` (and, through the J2 pipeline, criteria).
- Receiver: `vet init --source otlp::4318 --until <n traces> | --seconds <s>`.
- Library: `otlpSource(opts)` implements `SourceV1`; core's `casesFromTraces(traces)`
  turns `NormalizedTrace` into `Case`; core's completeness filter applies the status rules.

## Input contract

- OTLP/JSON `ExportTraceServiceRequest`: `resourceSpans[].scopeSpans[].spans[]`, lowerCamelCase
  field names, integer enums, hex trace/span ids (OTLP 1.11 JSON encoding).
- Ids: hex is the spec; some older exporters emit base64. Both are accepted and which encoding was
  seen is recorded. Whether ids are rewritten to hex is not pinned. Where the encoding is recorded
  is left to the reader (the IR has no field for it; `Span.attributes` is the only free slot).
- Files: `otlp:<file.json|dir>`; one `ExportTraceServiceRequest` per file. How a directory is walked
  is left to the reader (source-jsonl reads top-level files in name order).
- Receiver: `POST /v1/traces` on the given port (default 4318), `Content-Type: application/json`.
  An `application/x-protobuf` body gets HTTP 415 with body `{"error":"json only"}` and error code
  `OTLP_UNSUPPORTED_CONTENT_TYPE`. No gRPC (4317), no protobuf.
- A body that is not an `ExportTraceServiceRequest` → `OTLP_PARSE`, exit 2, naming the file.

## Source port

```ts
function otlpSource(opts: { files?: string[]; listen?: { port: number } }): SourceV1;
// capabilities: { streaming: true, content: 'maybe' }
// doRead({ signal }) yields one NormalizedTrace per OTLP traceId
```

`NormalizedTrace` is exactly the generated type from `trace.schema.json` (see "Schema alignment"):
`{traceId, spans[], messages[], dialect, dialectVersion?, schemaUrl?, completeness:
{contentCaptured, truncated, missingParents}, tokens?: {input?, output?, total?}}`. Spans from
all `resourceSpans`/`scopeSpans` sharing a `traceId` are grouped into one trace. A trace with zero
LLM spans yields no case and is counted.

## Dialects and detection cascade

`type OtlpDialect = 'gen_ai' | 'gen_ai_legacy' | 'openinference' | 'openllmetry' | 'vercel'`,
exported by `@vetkit/source-otlp`. Detection runs in that order; the first match wins. The trace
records the dialect and the resource's `schemaUrl` when present. A trace whose spans match more
than one dialect (dual emission) emits a `diag` warning and records the first detected.

Message-content precedence cascade (modelled on Langfuse `OtelIngestionProcessor`):

1. `gen_ai.input.messages` / `gen_ai.output.messages` / `gen_ai.system_instructions` on the span
   (JSON string or structured value) — `gen_ai`
2. the `gen_ai.client.inference.operation.details` event correlated by span id — `gen_ai`
3. legacy `gen_ai.prompt.{n}.*` / `gen_ai.completion.{n}.*` and the `gen_ai.content.*` span
   events — `gen_ai_legacy`
4. OpenInference `llm.input_messages.*` / `llm.output_messages.*`, fallback
   `input.value` / `output.value` — `openinference`
5. OpenLLMetry `llm.prompts.{n}` / `llm.completions.{n}`, `traceloop.entity.*` — `openllmetry`
6. Vercel `ai.prompt.messages`, `ai.response.text` / `ai.response.toolCalls`, `ai.toolCall.*` —
   `vercel`

Tool calls from every dialect map to `tool_call` / `tool_call_response` parts. The GenAI semconv
is Development status, so it may change: the normaliser pins the semconv commit it was written
against. Message order follows causal structure (parent/child, message index) first and timestamps
second, so spans out of timestamp order do not reorder turns.

## Tokens

Usage is read ONCE per LLM span and summed per trace; a child span never adds to its parent's
usage, and when old and new attribute names are both present on one span they count once. With no
usage on any LLM span, `tokens` is absent. Verified by the golden fixture
`fixtures/otlp/gen_ai-latest.json` with nested spans: tokens equal the sum of the leaf LLM spans.

## Completeness → Verdict.status

| Condition on the trace | `completeness` | `Verdict.status` |
|---|---|---|
| LLM spans carry no captured content (distinct from empty or redacted content) | `contentCaptured: false` | `content_not_captured` |
| `droppedAttributesCount` / `droppedEventsCount` > 0, attribute count at the 128 limit, broken JSON, a content length at a known limit (25 000 / 65 536 chars), or an external content reference (detected, not resolved) | `truncated: true` | `truncated` |
| a `parentSpanId` that resolves to no span in the trace | `missingParents: true` | `incomplete_trace` |

Such cases are excluded by core from content-dependent criteria and counted in the run summary
(the `excluded` object above); they are never scored. When several conditions hold the precedence
is the row order above (no precedence is otherwise specified; row order follows the order in which
the conditions are listed).

## Error codes

- `OTLP_PARSE` — not an `ExportTraceServiceRequest`; exit 2, message names the file.
- `OTLP_UNSUPPORTED_CONTENT_TYPE` — receiver got a non-JSON body; HTTP 415 `{error:'json only'}`.
- `SOURCE_EMPTY` — the source produced 0 traces; exit 2.

## Edge cases

Mixed dialects in one trace (diag warning, first wins); a trace with zero LLM spans (no case,
counted); base64 ids; spans out of causal order; attribute count at the 128 limit (truncated);
dropped counts > 0 (truncated); external content reference attributes (detect, mark truncated, do
not resolve).

## Scope

IN: reader, receiver, five dialects, detection cascade, token single-count, completeness statuses
and core exclusion, golden fixtures, the CLI seam.

OUT: protobuf, gRPC (:4317), collector processors, fragment stitching across traces by
conversation id (a risk left for later work), resolving external content references (detect only).

## Layout

`packages/source-otlp/src/{reader,normalize,dialects/<name>,completeness,receiver}`;
`packages/core/src/judge/completeness.ts`; `packages/cli/src/commands/init-otlp.ts` registering
the `otlp:` prefix through the J2 source-resolution seam (export name not pinned, see "Schema
alignment").

## Ownership gaps

- `packages/spec/src/errors.ts` (+ `errors.test.ts`) must gain `OTLP_PARSE`,
  `OTLP_UNSUPPORTED_CONTENT_TYPE`, `SOURCE_EMPTY`.
- `packages/cli/src/errors.ts` must map `SOURCE_EMPTY` and `OTLP_PARSE` to exit 2 by exact entry
  (the `SOURCE_*` prefix rule would otherwise make `SOURCE_EMPTY` exit 0).
- The CLI `otlp:` prefix depends on the J2 source-resolution seam.

## Design decisions

- Multi-dialect normaliser with recorded dialect and `schemaUrl`. OpenTelemetry is in scope in both
  directions. The OTel GenAI semantic conventions are Development status, so the normaliser pins the
  semconv commit.
- Precedence cascade modelled on Langfuse `OtelIngestionProcessor`.
- JSON-only receiver: Phoenix-style protobuf handling is out of scope, and OTLP/JSON is the
  spec's required encoding for HTTP.
- Statuses reuse the `Verdict.status` vocabulary (expected failures are discriminated-union data).
- No OTel SDK dependency is needed to read OTLP/JSON.
- Exporters may emit base64 ids: accept both, record which.
